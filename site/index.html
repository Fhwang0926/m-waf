DESIGNED FOR HOSTING PROVIDERS

웹서버 앞단을 바꾸지 않고
보호 범위를 넓힙니다.

중앙 프록시를 새로 구성하는 대신 기존 웹서버에 검사 모듈을 연결합니다. 고객 트래픽과 관리 트래픽을 분리해 호스팅 환경의 변경 범위를 줄입니다.

01

기존 서비스 경로 유지

클라이언트 요청은 Manager를 거치지 않습니다. Apache·Nginx에 연결된 ModSecurity가 현재 서버에서 검사하고 차단합니다.

02

여러 서버를 한 곳에서 운영

Manager에서 기업, 서버 그룹, 정책, 단계 배포, 패키지 상태와 보안 이벤트를 동일한 운영 범위로 확인합니다.

03

데이터와 관리 서버 자체 보관

Manager와 MariaDB를 호스팅사 인프라에 배포합니다. 고객 서버의 Agent는 Manager API로 발신 연결합니다.

DEPLOYMENT ARCHITECTURE

검사는 고객 서버에서,
운영은 Manager에서.

웹 요청 경로와 정책·로그 관리 경로가 분리됩니다. Manager 연결이 중단돼도 웹서버는 마지막으로 적용된 정책을 계속 사용합니다.

CENTRAL OPERATIONS

운영자가 필요한 상태를
한 화면 흐름으로 연결합니다.

서버 등록부터 정책 적용 결과와 보안 이벤트까지 Manager의 실제 메뉴 구조를 기준으로 운영합니다.

01

보호 서버

Agent 연결, 웹서버·통합 방식, CRS, 정책과 패키지 적용 상태를 확인합니다.

02

기업 정책

시스템 정책을 기준으로 민감도, 임계점수, URL·IP 예외와 제한된 추가 규칙을 배포합니다.

03

보안 이벤트

기업, 그룹, 서버, 위험도, 처리 결과, Rule ID와 요청 경로로 탐지·차단 기록을 조회합니다.

04

감사 및 시스템 운영

기업과 사용자 변경, 오픈소스 CRS, 시스템 정책과 관리자 작업 이력을 분리해 관리합니다.

SERVER ENROLLMENT

기업 설치 토큰 하나로
서버를 자동 등록합니다.

서버를 Manager에 미리 생성하지 않습니다. 설치 토큰과 검토한 스크립트를 고객 서버에 전달하면 환경 진단, 패키지 선택, 서버 등록과 Agent 인증서 발급이 이어집니다.

  1. 1
    Manager에서 기업 설치 토큰 생성유효기간과 선택적인 등록 한도 설정
  2. 2
    고객 서버에서 설치 스크립트 검토·실행CA로 Manager를 검증하고 토큰은 숨김 입력
  3. 3
    서버 자동등록 후 mTLS 전환재사용 토큰은 Agent 설정에 저장하지 않음
