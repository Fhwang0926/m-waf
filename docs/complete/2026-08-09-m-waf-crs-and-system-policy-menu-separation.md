# M-WAF CRS 관리와 시스템 정책 분리

## 작업 목적

시스템 관리자 화면에서 공식 CRS 원본을 관리하는 공급망 작업과, 검증된 CRS를 M-WAF 공통 보호 기준으로 게시하는 정책 작업을 서로 다른 메뉴와 화면 책임으로 구분했다.

## 반영 내용

- 시스템 관리자 사이드바의 `정책 공급망` 영역을 `CRS 관리`와 `시스템 정책`으로 분리했다.
- `CRS 관리`와 `시스템 정책`은 서로 독립된 활성 메뉴 상태를 사용한다.
- 감사 로그와 시스템 설정도 `운영 관리` 아래의 독립 메뉴로 분리했다.
- 기업 사용자와 기업 관리자에게는 시스템 관리자 전용 메뉴가 렌더링되지 않는 기존 RBAC를 유지했다.
- `/open-source-policies`를 GitHub 공식 OWASP CRS 동기화·서명·commit·digest·Rule/Setup 인덱스 확인 화면으로 정리했다.
- CRS 관리 화면에 마지막 동기화, 자동 동기화 주기, 최신 LTS와 Stable 버전을 표시했다.
- CRS 동기화만으로 시스템 정책이나 보호 서버가 변경되지 않는다는 책임 경계를 명시했다.
- CRS 상세 화면에서 기업 채택 수를 제거하고 원본 무결성, Rule/Setup, 시스템 정책과의 변경 비교, 정책 생성 준비 정보만 유지했다.
- `/system-policies`를 검증 CRS 기반의 M-WAF 공통 설정·Hot Rule 검증, 게시, 기업 영향과 단계 배포 확인 화면으로 정리했다.
- 시스템 정책 작성 화면의 `시스템 오버라이드` 표현을 `시스템 정책`으로 통일했다.
- 기존 GET/POST URL, 수동 동기화, 시작 시·주기 동기화, 정책 게시·회수, CSRF, 시스템 관리자 RBAC와 Agent API는 변경하지 않았다.

## 책임 경계

```text
GitHub OWASP CRS
  -> CRS 관리: 동기화·서명·digest·인덱스 검증
  -> 시스템 정책: CRS 선택·M-WAF 공통 설정 검증·불변 버전 게시
  -> 기업 정책: 업데이트 전략에 따른 채택
  -> Agent: 서명 artifact 단계 배포
```

## 확인 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- Go 템플릿 파싱, 전체 패키지·테스트 소스 로딩과 `git diff --check`를 정적으로 확인했다.
- 권한별 메뉴 표시와 CRS 관리·시스템 정책의 독립 활성 상태를 검증하는 테스트 소스를 갱신했다.

## 수행하지 않은 검증

- 저장소 지침에 따라 자동 테스트와 프론트엔드 빌드는 실행하지 않았다.
- 실제 브라우저 렌더링과 동기화 요청은 수행하지 않았다.
- DB migration, init/reset, 데이터 변경, Manager 재시작과 실제 정책 게시·배포는 수행하지 않았다.
