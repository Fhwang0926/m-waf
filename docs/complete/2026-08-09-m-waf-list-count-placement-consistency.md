# M-WAF 목록 수량 표시 위치 통일 완료

## 작업 목적

목록 화면에서 전체 수와 현재 표시 수가 같은 값으로 반복되던 문제를 정리하고, 전체 수·검색 결과 수·페이지 수의 의미와 위치를 통일했다.

## 공통 기준

- 필터 전 전체 수는 페이지 제목 설명 아래에 한 번만 표시한다.
- 목록 패널의 상시 `N개 표시` 배지는 제거한다.
- 검색 조건이 적용된 경우에만 검색 영역에 `검색 결과 N개`를 표시한다.
- 페이지가 나뉘는 목록은 목록 제목에 현재 페이지 건수만 표시하고 페이지 번호는 하단 이동 영역에 둔다.
- 탭에 전체 수가 표시되면 탭 내부 제목에서 같은 수를 반복하지 않는다.

## 반영 화면

- 보호 서버: 전체 서버 수는 상단에 유지하고 필터 적용 시 검색 결과 서버 수만 표시한다.
- 보호 정책: 목록의 상시 표시 수를 제거하고 필터 결과 수를 검색 조건과 함께 표시한다.
- 서버 그룹: 전체 수 단위를 간결하게 통일하고 필터 결과 수를 검색 영역으로 이동했다.
- 기업 관리: 전체 수를 `전체 N곳`으로 정리하고 필터 결과 수도 같은 단위를 사용한다.
- 사용자 관리와 기업별 사용자: 상시 표시 수를 제거하고 필터 사용 시에만 결과 인원을 표시한다.
- 시스템 정책 변경 이력: 전체 수는 탭에만 유지하고 필터 결과 수는 검색 동작 옆에 표시한다.
- 보안 이벤트와 감사 로그: 현재 페이지 건수와 하단 페이지 번호를 분리했다.

## 유지한 화면

- IP 정책과 기업 상세 탭의 수량은 해당 섹션 범위를 설명하므로 유지했다.
- 기업 적용 현황은 상단에 한 번만 표시되어 유지했다.
- CRS 목록과 Rule 목록의 전체 수·현재 페이지 수는 페이지 이동에 필요한 서로 다른 정보이므로 유지했다.

## 확인 범위

- 전체 수와 필터 후 목록 수를 만드는 Handler 데이터 흐름을 정적으로 확인했다.
- 변경된 템플릿의 조건과 수량 단위, 중복 표시 여부를 확인했다.
- `git diff --check`를 확인했다.

## 수행하지 않은 검증

- 프로젝트 지침에 따라 프론트엔드 빌드와 자동 테스트는 수행하지 않았다.
- 실행 중인 Manager의 재시작과 변경 후 로그인 화면 확인은 수행하지 않았다.
- DB 조회·변경, init, reset, 스키마 마이그레이션은 수행하지 않았다.
