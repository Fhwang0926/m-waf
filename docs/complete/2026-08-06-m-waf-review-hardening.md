# M-WAF 구현 검토 후 안정성 보완

## 완료 범위

- 원격 고정 명령은 실제 `systemctl` 요청이 성공한 뒤 완료 ID를 저장하며, Manager가 `ACCEPTED` 상태 명령을 다시 전달할 수 있게 해 Agent 중단 후 복구 경로를 보완했다.
- 서버별 명령 예약을 트랜잭션과 행 잠금으로 직렬화해 동시에 두 명령이 대기 상태로 생성되는 경쟁 조건을 제거했다.
- WAF 감사 로그 한 요청이 Agent 배치 상한 500건을 초과해도 메시지 위치를 checkpoint에 기록해 유실 없이 여러 배치로 이어 보내도록 보완했다.
- Agent 이벤트 spool에 기본 512 MiB 상한을 추가하고 설치 설정에도 같은 값을 기록했다.
- 이벤트 수집 시 미래 시각을 제한하고, 이벤트·수집 배치·관리자 감사 로그를 각각 시간 제한 내에서 반복 정리하도록 순환 삭제를 보완했다.
- 마지막 heartbeat가 2분을 넘은 서버를 관리자 화면에서 `OFFLINE`으로 표시한다.
- 이벤트 화면에 서버, 차단 여부, 위험도, URL·Rule ID·메시지 필터와 100건 단위 페이지 이동을 추가했다.
- ModSecurity 차단 판정을 HTTP 403뿐 아니라 접근 거부 메시지와 CRS 차단 평가 규칙까지 함께 사용하도록 보완했다.
- 새 정책·패키지 배포가 기존 대기 요청을 대체하면 `SUPERSEDED`로 기록하고 정책 목록에 대체 건수를 표시한다.
- 패키지 설치 성공은 Agent 재시작 후 설치된 Agent·모듈 버전이 목표와 일치할 때만 보고한다.
- 릴리스 번들 생성기가 직전 서명 번들의 활성 패키지 3종을 검증해 N-1 롤백 대상으로 포함하고 현재 패키지의 `rollback_id`를 연결한다. 최초 `v0.1.0` 외 릴리스는 이전 `latest`를 읽지 못하면 실패한다.
- Ubuntu 24.04 배포판 ModSecurity 패키지를 사용하는 실제 패키지 구조에 맞춰 웹서버 exact build hash 결합을 제거하고, 설치기는 x86_64와 Ubuntu 패키지로 설치된 Apache/Nginx만 허용한다.
- 모든 관리자가 **내 계정**에서 본인 비밀번호를 변경할 수 있으며, 변경 후 기존 서명 세션은 비밀번호 해시 기반 credential tag 검증으로 무효화된다.
- 관리자 감사 로그 INSERT 오류를 무시하지 않고 구조화 로그로 남긴다.
- 인증서 갱신은 새 인증서의 첫 mTLS 요청에서 serial을 원자적으로 교체해 갱신 응답 유실은 복구하면서 이전 인증서의 장기 병행 사용은 막는다.

## 유지한 안전 경계

- WebSocket이나 Agent 수신 포트는 추가하지 않았고 기존 HTTPS polling만 사용한다.
- 임의 셸 명령 입력은 추가하지 않았으며 Agent/서버 재시작·중지 네 가지 고정 명령만 유지한다.
- 기업 사용자와 기업 관리자는 자기 기업만 운영하고, 사용자·권한 관리는 기업 관리자 이상으로 제한하며, 시스템 관리자만 전체 기업을 관리한다.
- DB migration이나 데이터 초기화·재설정은 실행하지 않았다.
- 그룹 정책 배포는 현재 그룹 구성원에 대한 일괄 배포이며, 향후 추가되는 구성원에게 자동 상속하는 영구 그룹 정책은 별도 데이터 모델 변경이 필요해 이번 범위에 포함하지 않았다.

## 확인 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- `git diff --check`, shell 문법 검사, GitHub Actions YAML 파싱을 확인했다.
- `go list ./...`로 패키지 구성을 확인했으며 기본 Go module stat cache는 작업 공간 외부 쓰기 제한 경고가 있었지만 패키지 목록은 정상 반환됐다.
- 저장소 지침에 따라 Go/프론트엔드 빌드, 자동 테스트, 브라우저 실행, DB migration 적용, 실제 패키지 설치·재시작은 수행하지 않았다.
