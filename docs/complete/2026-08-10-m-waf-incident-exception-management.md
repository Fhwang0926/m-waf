# 탐지 이벤트 기반 기업 예외 정책 관리 완료

## 변경 내용

- 탐지 이벤트 상세의 즉시 예외 버튼을 `예외 정책 검토` 한 개로 통합했다.
  - 입력 항목, 특정 URL, 전체 요청 범위를 검토 화면에서 선택한다.
  - 운영 사유와 만료 기간, 연결 서버 전체 적용 영향을 확인해야 게시할 수 있다.
  - 전체 요청 예외와 영구 예외는 기업 관리자 이상으로 제한했다.
- 예외 게시 전에 기업 범위, 현재 정책 개정본, 진행 중인 rollout, 원본 Rule, 연결 서버, 중복·포괄 예외를 다시 검증한다.
- 예외 생성은 시스템 정책과 CRS를 변경하지 않고 기업 정책의 새 서명 불변 개정본과 `UPDATE` rollout을 생성한다.
- 기업 정책의 `예외·간편 규칙` 탭을 예외 관리 목록으로 변경했다.
  - 상태, 범위, Rule, URL·입력 조건, 원본 이벤트, 운영 사유, 만료 시각을 표시한다.
  - 개별 예외 해제도 현재 설정을 직접 삭제하지 않고 새 개정본과 단계 배포로 처리한다.
- 만료된 기업 예외는 기존 IP 정책 만료 주기와 함께 매시간 확인한다.
  - 진행 중인 rollout이 있으면 보류한다.
  - 제거 가능한 시점에 만료 예외를 제외한 새 개정본을 만들고 감사 로그를 기록한다.
- 일반 보호 정책 변경 시 탐지 이벤트 예외의 사유와 만료 정보가 유지되도록 기존 구조화 예외 메타데이터를 보존한다.

## 호환성

- 기존 `/policies/{id}/exceptions/from-incident` 경로는 호환용으로 유지했다.
- 신규 검토·관리 경로를 추가했으며 기존 Agent API, 정책 artifact 형식과 DB 스키마는 변경하지 않았다.
- 기업 범위는 세션의 `ScopeEnterpriseID()`로 다시 검사하고 다른 기업의 이벤트·정책 조합은 허용하지 않는다.

## 검증

- 만료 기간 권한, 중복·포괄 예외, 이벤트 사유 표시, 일반 정책 변경 시 메타데이터 보존 회귀 테스트를 추가했다.
- `go test ./internal/manager`와 `go test ./cmd/mwaf-manager`를 통과했다.
- 실행 중인 Manager의 `/health/live`, `/health/ready`가 HTTP 200을 반환하는 것을 확인했다.
- `gofmt`와 `git diff --check`를 확인했다.

## 수행하지 않은 검증

- 저장소 지침에 따라 프론트엔드 빌드와 프론트엔드 테스트는 수행하지 않았다.
- DB init, reset, migration 적용 또는 실제 예외 생성·해제 같은 DB 쓰기 검증은 수행하지 않았다.
- 실제 Agent에 예외 artifact를 배포하거나 Apache/Nginx configtest와 rollback을 수행하지 않았다.
