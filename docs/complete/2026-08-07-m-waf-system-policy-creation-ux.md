# M-WAF 시스템 정책 생성 흐름 UX 개선 완료

## 완료 범위

- 시스템 관리자 메뉴를 `시스템 정책 > CRS 소스 / 정책 버전` 구조로 정리했다.
- CRS 소스 화면에 현재 기준 정책, 최근 검증 소스, 새 CRS 후보, 패키지 준비 상태를 추가했다.
- CRS별 작업을 `최초 정책 만들기`, `이 CRS로 새 버전 만들기`, `현재 정책에서 사용 중`, `상세 보기`로 구분했다.
- 정책 버전 화면에 현재 정책·CRS·적용 범위·배포 상태와 게시 완료 후속 작업을 추가했다.
- 사용자 화면의 CRS 정책 생성 용어를 `마이그레이션`에서 `새 정책 버전 만들기`로 변경했다. 기존 URL과 내부 핸들러 이름은 호환성을 위해 유지했다.
- 기존 단일 장문 폼을 기준 선택, 변경 확인, 보호 설정, 예외·Rule, 검증·게시의 5단계 화면으로 변경했다.
- 일반 보호 설정은 바로 표시하고 전체 CRS Setup, Target·조건부 예외, 원시 Service Rule은 고급 설정으로 접었다.
- 선택한 CRS의 diff API를 사용해 설정 전에 추가·삭제·내용 변경 Rule과 Setup 변경을 표시한다.
- 마지막 단계에서 기존 시스템 정책 검증 API를 자동 호출하고 서버 호환성, 롤백 준비, 기업별 자동·수동·고정 전략 영향을 표시한다.
- 입력 변경 시 기존 validation digest를 폐기하고 재검증 전에는 게시할 수 없게 했다.
- 서버 field error를 작성 단계와 입력 필드에 연결하고 고급 입력 구문 오류도 정확한 단계에 표시한다.
- 게시 완료 후 `published` 정책 참조로 결과 카드를 표시하고 기업 적용, 승인 대상, 진행 중 배포, 게시 버전으로 연결한다.

## 유지한 경계

- CRS 확인만으로 시스템 정책을 자동 게시하지 않는다.
- 게시된 정책을 덮어쓰지 않고 새 불변 버전으로만 생성한다.
- 최종 게시 시 서버가 정책 검증과 validation digest를 다시 계산한다.
- DB 스키마, Agent 프로토콜, Manager-Agent polling 구조를 변경하지 않았다.
- 신규 프론트엔드 라이브러리를 추가하지 않았다.

## 검증 결과

- `git diff --check` 통과
- `go test ./internal/manager -run 'Test(AdminStatusLabels|NavigationVisibilityByRole|SystemPolicy)' -count=1` 통과
- `go test ./internal/manager -count=1` 통과
- 현재 실행 중인 개발 Manager가 변경 이후 다시 생성되어 `127.0.0.1:8443`에서 수신 중인 것을 확인했다.
- 로그인 화면과 최신 `app.js`가 HTTP 200으로 제공되고 `initializeSystemPolicyWizard`가 포함된 것을 확인했다.
- 비인증 `/system-policies` 요청이 기존대로 `/login` 303과 `Cache-Control: no-store`를 반환하는 것을 확인했다.

## 수행하지 않은 검증

- 프로젝트 지침에 따라 프론트엔드 빌드와 별도 프론트엔드 테스트는 수행하지 않았다.
- DB init/reset 및 스키마 마이그레이션은 수행하지 않았다.
- 브라우저 연결에 인증된 Manager 세션이 없어 보호된 CRS 소스·정책 버전 화면의 실제 클릭 검수와 390px 화면 검수는 수행하지 못했다. 템플릿 렌더링 테스트와 반응형 CSS 정적 검토로 대체했다.
