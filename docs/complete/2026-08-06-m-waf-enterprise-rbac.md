# M-WAF 최초 시스템 관리자 및 기업 권한 체계 구현

## 완료 범위

- 최초 접속 시 `/setup`에서 시스템 관리자 사용자명, 표시 이름, 비밀번호를 설정하도록 변경
- 최초 시스템 관리자가 생성된 뒤 setup 경로를 자동으로 닫도록 처리
- 환경변수와 secret 파일에 저장하던 단일 관리자 계정을 DB 기반 다중 계정으로 전환
- `시스템 관리자 > 기업 관리자 > 기업 사용자`의 고정 역할 체계 적용
- 시스템 관리자용 기업 등록 및 전체 사용자 관리 화면 추가
- 기업 관리자용 소속 기업 사용자·관리자 추가 및 목록 화면 추가
- PBKDF2-SHA256 기반 비밀번호 hash 저장과 로그인 시 활성 사용자 재확인 적용
- 로그인 session에 사용자 ID, 역할, 기업 범위를 포함하고 매 요청마다 현재 계정 상태를 다시 조회

## 역할별 권한

| 역할 | 조회 범위 | 운영 권한 | 사용자 관리 |
|---|---|---|---|
| 시스템 관리자 | 모든 기업, 미지정 legacy 서버 | 모든 서버 등록 및 정책 배포 | 기업 생성, 기업 관리자와 기업 사용자 생성 |
| 기업 관리자 | 자기 기업만 | 자기 기업 서버·그룹·정책 운영 | 자기 기업의 사용자·관리자 및 권한 관리 |
| 기업 사용자 | 자기 기업만 | 자기 기업 서버·그룹·정책 운영 | 없음 |

## 기업 데이터 격리

- `servers`와 `enrollment_tokens`에 `enterprise_id`를 추가했다.
- 서버 등록 token 생성 시 기업을 반드시 지정한다.
- Agent enrollment 시 token의 기업을 신규 서버에 그대로 연결한다.
- 서버, WAF 이벤트, 정책 대상 목록과 Admin API 조회에 session 기업 범위를 강제한다.
- 정책 배포 시에도 대상 서버가 로그인 사용자의 기업에 속하는지 DB transaction 안에서 다시 확인한다.
- 기존 서버는 migration 후 `enterprise_id=NULL`로 남으며 시스템 관리자에게만 보인다. 신규 기업 사용자는 접근할 수 없다.

## 관리자 화면

- 최초 시스템 관리자 설정
- 공통 역할 및 소속 기업 표시 navigation
- 기업 등록 및 기업 목록
- 역할을 지정한 기업 사용자·관리자 생성 및 사용자 목록
- 시스템 관리자 화면의 기업별 서버·이벤트 표시
- 기업 사용자에게 서버 등록·제어, 그룹, 정책 배포·승인·재시도·롤백 제공
- 기업 사용자에게 사용자 관리 메뉴와 API는 제공하지 않음
- 자기 관리자 권한 해제와 마지막 활성 기업 관리자 비활성화·삭제 차단

## 배포 설정 변경

- `MWAF_ADMIN_USERNAME`, `MWAF_ADMIN_PASSWORD_FILE`, `mwaf_admin_password` secret을 제거했다.
- `prepare.sh`는 초기 관리자 비밀번호를 생성하지 않고 Admin UI 최초 설정을 안내한다.
- 기존 관리자 password secret 파일이 디스크에 남아 있더라도 새 코드에서는 사용하지 않는다.

## 확인 범위

- `gofmt`로 변경된 Go 파일 형식을 정리했다.
- `git diff --check`에서 whitespace 오류가 없음을 확인했다.
- 운영 DB migration은 실행하지 않았다.
- 지침에 따라 Go build/test와 frontend build/test를 수행하지 않았다.
- 실행 중인 Manager가 없어 로그인 및 역할별 실제 브라우저 동작은 확인하지 않았다.
