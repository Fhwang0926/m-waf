도입 판단

설치 전에 세 가지를
먼저 확인하십시오

M-WAF는 범용 프록시 WAF가 아닙니다. Ubuntu 기반 Apache·Nginx 서버를 직접 운영하고, 기존 트래픽 경로를 유지하려는 호스팅 환경을 대상으로 합니다.

적합한 환경

이런 운영팀에 맞습니다

  • 여러 고객의 Apache·Nginx를 직접 운영
  • 80/443 경로를 중앙 프록시로 우회하기 어려움
  • 오픈소스 ModSecurity·CRS를 중앙 관리하고 싶음
  • Manager와 데이터를 자체 인프라에 보관해야 함
사전 조건

다음 준비가 필요합니다

  • 별도 Linux Manager 서버와 Docker Compose
  • 고객 서버에서 Manager Agent API로 나가는 연결
  • Ubuntu 24.04 amd64 고객 서버
  • 커스텀 빌드는 호환 Connector 사전 설치
현재 범위 밖

MVP에서 지원하지 않습니다

  • 트래픽 프록시·로드밸런서 기능
  • RPM 계열, ARM64, Windows, OpenResty
  • Connector 자동 컴파일과 ABI 자동 보정
  • Manager HA와 공식 대규모 용량 보증
핵심 원칙

고객 웹 요청은 Manager로 보내지 않습니다. Manager는 정책과 패키지를 배포하고 Agent가 전송한 상태·감사 이벤트를 저장합니다.

잘못된 정책

서명과 SHA-256을 확인하고 configtest가 실패하면 이전 정책으로 복원합니다.

고객 방화벽

Agent용 인바운드 포트는 없습니다. 고객 서버에서 Manager Agent API로 연결할 수 있어야 합니다.

서버 등록과 설치

고객 서버 한 대를
등록하는 실제 순서

호스팅사 엔지니어는 Manager에서 토큰을 발급하고 설치 명령을 고객 서버에서 한 번 실행합니다. 설치기는 환경에 맞는 두 DEB만 내려받습니다.

  1. 01
    Manager에서 기업 설치 토큰 생성

    기업만 선택하고 유효 기간과 선택적인 서버 등록 한도를 지정합니다. 서버를 미리 만들 필요는 없습니다.

  2. 02
    CA·설치 스크립트·토큰 전달

    Manager가 제공한 설치 블록을 검토하고, 기업 설치 토큰은 별도의 보호된 입력이나 비밀 파일로 전달합니다.

  3. 03
    OS·웹서버·Connector 사전진단

    Ubuntu, amd64, 바이너리 경로, Connector 로드와 전용 include 경로를 확인합니다.

  4. 04
    서명 번들에서 DEB 두 개 설치

    SHA-256을 검증한 Agent와 선택한 웹서버 통합 패키지만 APT로 설치합니다.

  5. 05
    서버 자동등록과 Agent 인증서 발급

    Manager가 토큰을 단기 일회용 등록 세션으로 교환합니다. configtest가 끝나면 서버가 자동 생성되고 Agent별 mTLS 인증서로 전환합니다.

상용 소프트웨어 WAF와의 차이

DeepFinder와 같은 운영 모델,
더 좁은 MVP 범위

두 제품 모두 보호 서버에서 검사하고 중앙 Manager에서 운영하는 모델입니다. M-WAF는 ModSecurity·OWASP CRS 기반의 공개 구성과 최소 기능에 집중하며, 상용 제품의 광범위한 정책·분석·지원 환경을 아직 제공하지 않습니다.

선택 기준

공개 구성과 좁은 지원 범위로 직접 운영하려면 M-WAF를 검토할 수 있습니다. 다양한 OS, 세분화된 도메인 정책, 정기 보고서, 공식 용량과 기술지원이 필수라면 현재 MVP만으로는 대체할 수 없습니다.
