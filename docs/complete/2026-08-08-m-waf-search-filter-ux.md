# 관리자 검색·필터 UX 개선 완료

## 완료 범위

- 관리자 화면의 GET 검색 폼을 전체 점검하고 공통 검색 패턴을 적용했다.
- 기본 화면에는 사용 빈도가 높은 검색어와 대표 상태만 노출한다.
- 시간, 기업, 그룹, 서버, 권한, 업데이트 전략 등 보조 조건은 `상세 조건` 영역에서 펼쳐 사용한다.
- 상세 조건이 적용된 상태로 다시 열면 접기 영역도 자동으로 펼쳐진다.
- 검색 결과에 적용된 조건은 배지로 표시하고, 이벤트 화면은 조건별 제거 기능을 유지한다.
- 아무 조건도 적용되지 않았을 때는 초기화 버튼을 숨기고, 조건이 있을 때만 `조건 지우기` 링크를 표시한다.
- 주요 실행 버튼 문구를 `검색` 또는 `범위 적용`으로 통일했다.
- 검색 입력은 브라우저 기본 지우기 기능을 사용할 수 있도록 `type="search"`를 적용했다.
- 760px 이하에서는 검색 필드와 상세 조건을 한 열로 전환하고 실행 버튼을 넓게 표시한다.

## 적용 화면

- 관리자 감사 로그
- 보안 이벤트
- 운영 현황
- 시스템 정책 버전
- 기업 정책
- 보호 서버
- 사용자 관리
- 서버 그룹
- 기업 관리
- CRS Rule Set

설치 화면의 기업 선택은 검색이 아니라 신규 Agent의 필수 설치 범위를 결정하는 제어이므로 기존 단일 선택 흐름을 유지했다.

## 추가 정리

- 이벤트 기간을 적용 조건 배지에 포함했다.
- 이벤트 위험도 숫자를 치명적, 오류, 주의, 알림, 정보 레이블로 표시한다.
- 기존 URL 쿼리 이름과 서버 필터 동작은 유지했다.

## 검증

- `gofmt`를 적용했다.
- `git diff --check`를 통과했다.
- 템플릿별 `{{`와 `}}` 개수가 일치하는지 정적으로 확인했다.
- DB 변경과 데이터 초기화는 수행하지 않았다.
- 로컬 `https://127.0.0.1:8443` Manager가 실행 중이 아니어서 로그인된 실제 화면은 확인하지 못했다.
- 프로젝트 규칙에 따라 프론트엔드 빌드와 브라우저 조작 테스트는 실행하지 않았다.
