# M-WAF 관리자 UI/UX 개선 완료

## 기준과 목적

- M-WAF `v0.1.7`의 설치 토큰, 역할 권한, 시스템·기업 정책, rollout·rollback과 CLI 비밀번호 복구 동작을 유지하면서 관리자 화면의 정보 구조와 운영 안전성을 정리했다.
- 시스템 정책은 조회 전용, 기업 정책은 기업 운영자가 관리하는 기존 경계를 유지했다.
- 작업 중 함께 존재한 기업 운영 종료 및 안전 삭제 흐름을 제거하거나 우회하지 않고 현재 화면 구조에 맞춰 보존했다.

## 공통 UI

- `app.css`에 색상, 간격, 모서리, 콘텐츠 폭, 컨트롤, 버튼, 알림, 배지, 툴팁과 반응형 스타일을 통합했다.
- 중복 `policy.css`를 제거하고 모든 화면의 `select`, `input`, `textarea`, `button`을 최소 44px 높이의 같은 조작 체계로 맞췄다.
- 전체 화면 배경을 반복되지 않는 단일 그라데이션으로 바꾸고, 패널 전역 스크롤을 제거했다. 표와 코드 블록만 전용 영역에서 스크롤한다.
- 데스크톱 2단 내비게이션, 태블릿 가로 스크롤 힌트, 모바일 `details/summary` 메뉴를 적용했다.
- 시스템 관리 메뉴는 시스템 관리자에게만 보이며, 기업 관리자는 사용자 관리를 포함하고 기업 사용자는 운영 메뉴만 볼 수 있다.
- 내부 상태값은 도메인 값은 바꾸지 않고 한국어 라벨과 색상 배지로 표시하며, 필요한 원본 값은 `title` 보조 정보로 유지한다.
- Agent, 통합 모듈, mTLS, CRS, 시스템 정책, 업데이트 전략, 개정본, rollout, 소스 commit과 digest 등에 키보드 포커스 가능한 설명을 추가했다.

## 운영 화면

- 대시보드는 기업 범위를 적용한 읽기 전용 집계로 활성 서버, 2분 heartbeat 기준 온라인 서버, 최근 24시간 이벤트와 차단 이벤트를 표시한다. 최근 서버 목록의 10건 제한을 전체 서버 수로 사용하던 동작을 제거했다.
- Manager와 package bundle 준비 상태를 숫자 카드와 분리해 화면 상단에 표시한다.
- 서버, 이벤트, 기업 정책, 정책 생성·상세, 서버 그룹, 설치 및 등록, 기업·사용자 관리, 시스템 정책·설정, 내 계정, 로그인과 최초 설정 화면의 정보 위계와 반응형 레이아웃을 통일했다.
- 이벤트 필터 요약, 현재 페이지와 조회 건수, 포커스 가능한 전체 URI·Rule 메시지를 제공한다.
- 정책 생성 폼은 시스템 정책·대상, 기본 정보·전략, 모드·CRS 설정, 예외·사용자 규칙의 네 구역으로 나눴다.
- 정책 상세의 개정본 충돌은 최신 상세 화면을 HTTP 409로 다시 표시하고 새로고침 후 재시도 안내를 제공한다.

## 입력 복구와 위험 작업

- 브라우저 HTML 폼 오류는 평문 대신 동일 화면 또는 공통 한국어 오류 화면으로 표시한다.
- 기업, 역할, 이름, 기간, 정책 설정과 사용자 규칙 같은 안전한 값은 오류 후 유지한다.
- 비밀번호, 기업 설치 토큰과 일회용 토큰 원문은 오류 후 다시 채우거나 브라우저 저장소에 보관하지 않는다.
- 기업 설치 토큰 폐기, 서버 그룹 삭제, 정책 롤백, 기존 정책 전환, 사용자 삭제, 서버 등록 해제와 서버·Agent 중지에는 확인 입력을 추가했다. 서버 핸들러도 `confirm=confirmed`를 검증한다.
- 로그인, 최초 설정, 설치 토큰 원문 HTML과 토큰을 반환하는 관리자 JSON 응답에 `Cache-Control: no-store`를 적용했다.

## 설치 및 등록

- 기업 설치 토큰 생성, 한 번만 표시되는 원문, 안전한 설치 명령, 등록 상태와 폐기 순서로 화면을 재구성했다.
- 토큰과 설치 명령 복사는 표준 Clipboard API만 사용하는 최소 `app.js`로 구현하고 결과를 `aria-live`에 전달한다.
- Clipboard API를 사용할 수 없으면 원문 코드 블록에 포커스를 이동하고 수동 복사를 안내한다.
- `--install-token-stdin`, 기업 토큰 재사용 의미와 단일 서버 일회용 토큰 호환 기능은 변경하지 않았다.

## 인터페이스와 호환성

- 기존 GET/POST URL, CSRF, 세션, 역할 권한, 기업 범위 검사와 감사 로그를 유지했다.
- Agent desired-state API, 설치 API와 Admin JSON API의 응답 구조를 변경하지 않았다.
- 이 UI/UX 범위에서는 데이터베이스 스키마나 migration을 추가하지 않았고, 대시보드에는 기존 테이블을 대상으로 하는 읽기 전용 집계만 추가했다. 작업 트리에 함께 존재하는 기업 생명주기 migration은 별도 변경이며 이 작업에서 수정하거나 적용하지 않았다.
- 시스템 관리자 비밀번호 복구는 기존 CLI 전용 동작으로 유지했으며 로그인 화면에 복구 링크나 우회 기능을 추가하지 않았다.

## 검증 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- 상태 라벨과 권한별 내비게이션 렌더링 검증 소스를 추가했다.
- 중복 `policy.css` 참조, 전역 패널 overflow, 토큰의 브라우저 저장소 사용, 정적 스크립트 범위를 소스에서 확인했다.
- `git diff --check`를 확인했다.
- 저장소 지침과 요청 범위에 따라 자동 테스트, Go·프론트엔드 빌드, 브라우저 실행, 실제 DB 조회 및 migration 적용은 수행하지 않았다.
