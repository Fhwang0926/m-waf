# M-WAF 사용자 및 접근 권한 관리

## 목적

이 문서는 M-WAF 관리자 콘솔의 현재 사용자 역할, 기업 범위, 계정 수명주기와 운영 보호 규칙을 정의한다. 화면의 메뉴 표시가 아니라 Manager의 서버 측 권한 검사를 기준으로 한다.

## 권한 모델

M-WAF는 다음 세 역할을 계층형으로 사용한다.

| DB 역할 | 화면 표시 | 의미 |
|---|---|---|
| `enterprise_user` | 기업 사용자 | 자기 기업의 모니터링과 실제 운영을 수행하는 운영자 |
| `enterprise_admin` | 기업 관리자 | 자기 기업을 운영하고 사용자와 권한까지 관리하는 관리자 |
| `system_admin` | 시스템 관리자 | 전체 기업 운영과 M-WAF 시스템 영역을 관리하는 전역 관리자 |

`enterprise_user`는 조회 전용 계정이 아니다. 별도의 viewer 또는 감사 전용 역할은 현재 제공하지 않는다.

### 기능별 권한

| 기능 | 기업 사용자 | 기업 관리자 | 시스템 관리자 |
|---|---:|---:|---:|
| 대시보드·보호 서버·보안 이벤트 조회 | 자기 기업 | 자기 기업 | 전체 기업 |
| 서버 명령·패키지 배포·등록 해제 | 자기 기업 | 자기 기업 | 전체 기업 |
| 기업 정책 생성·수정·전략 변경 | 자기 기업 | 자기 기업 | 전체 기업 |
| 정책 rollout 승인·재시도·롤백 | 자기 기업 | 자기 기업 | 전체 기업 |
| 서버 그룹 생성·수정·삭제 | 자기 기업 | 자기 기업 | 전체 기업 |
| 설치·등록 토큰 생성·폐기 | 자기 기업 | 자기 기업 | 전체 기업 |
| 기업 사용자·관리자 관리 | 불가 | 자기 기업 | 전체 기업 |
| 기업 생성·운영 종료 | 불가 | 불가 | 가능 |
| CRS 소스·시스템 정책 관리 | 불가 | 불가 | 가능 |
| 감사 로그·시스템 설정 | 불가 | 불가 | 가능 |

역할 검사는 `enterprise_user < enterprise_admin < system_admin` 순서로 적용한다. 메뉴를 숨기는 것과 별개로 각 변경 라우트에서도 필요한 최소 역할을 다시 검사한다.

## 기업 범위

- 모든 관리자 콘솔 계정은 정확히 하나의 활성 기업에 소속된다.
- 기업 사용자와 기업 관리자의 읽기·변경 범위는 세션에 저장된 소속 기업으로 강제한다.
- 요청에서 다른 `enterprise_id`를 보내더라도 기업 계정에는 적용하지 않는다.
- 시스템 관리자는 하나의 내부 운영 기업에 소속되지만 `system_admin` 역할로 전체 기업을 조회하고 관리할 수 있다.
- 시스템 관리자의 변경 요청에 대상 기업이 명시되지 않으면 자신의 내부 운영 기업을 기본 범위로 사용한다.
- 시스템 관리자 소속 기업은 삭제하거나 운영 종료할 수 없다.

최초 설정에서는 `M-WAF 시스템 운영` 기업과 최초 시스템 관리자 계정을 하나의 transaction으로 생성한다. 기존 시스템 관리자도 전진형 migration을 통해 전용 운영 기업에 소속된다.

## 계정 생성과 관리

### 최초 시스템 관리자

- `/setup`은 삭제되지 않은 관리자 계정이 하나도 없을 때만 열린다.
- 최초 설정은 시스템 관리자 한 명과 내부 운영 기업을 생성한다.
- 현재 관리자 UI에는 추가 시스템 관리자 생성 기능이 없다.
- 시스템 관리자 계정은 사용자 관리 화면에서 읽기 전용으로 표시한다.
- 시스템 관리자는 `내 계정`에서 자신의 비밀번호를 변경할 수 있다.
- 비밀번호를 분실한 활성 시스템 관리자는 배포 환경의 CLI 복구 명령을 사용한다.

DB 역할과 기업 구조는 여러 시스템 관리자 행을 저장할 수 있지만, 추가·비활성화·삭제를 포함한 공식 다중 시스템 관리자 운영 흐름은 아직 제공하지 않는다.

### 기업 사용자와 기업 관리자

- 시스템 관리자는 활성 기업을 선택해 기업 사용자 또는 기업 관리자를 생성할 수 있다.
- 기업 관리자는 자기 기업에 기업 사용자와 다른 기업 관리자를 생성할 수 있다.
- 기업 사용자는 사용자 관리 화면과 관련 라우트에 접근할 수 없다.
- 생성 시 지정한 사용자명과 소속 기업은 수정할 수 없다.
- 표시 이름, 역할, 활성 상태와 비밀번호는 권한 있는 관리자가 변경할 수 있다.
- 비밀번호를 변경하지 않을 때는 비밀번호 입력란을 비워 둔다.
- 삭제는 계정 행을 제거하지 않고 `deleted_at`과 비활성 상태를 기록하는 soft delete로 처리한다.
- 사용자명은 기업별이 아니라 전체 시스템에서 유일하다.

기업 관리자는 여러 명 둘 수 있으며 별도의 최대 인원 제한은 없다. 다만 기업 생성과 첫 기업 관리자 생성은 분리되어 있으므로 신규 기업은 시스템 관리자가 첫 관리자를 추가하기 전까지 기업 관리자가 0명일 수 있다.

## 관리자 유실 방지

다음 작업은 서버에서 차단한다.

- 기업 관리자가 자기 역할을 기업 사용자로 변경
- 기업 관리자가 자기 계정을 비활성화
- 기업 관리자가 자기 계정을 삭제
- 마지막 활성 기업 관리자를 강등·비활성화·삭제
- 기업 관리자가 다른 기업의 계정을 조회·변경
- 기업 사용자 또는 기업 관리자를 `system_admin`으로 변경
- 사용자 관리 화면에서 시스템 관리자 계정을 변경하거나 삭제

마지막 활성 기업 관리자 검사는 대상 사용자와 같은 기업의 다른 활성 관리자 행을 transaction에서 잠근 뒤 수행한다. 동시 요청으로 모든 기업 관리자가 제거되는 상황을 방지한다.

## 인증과 세션

- 비밀번호는 PBKDF2-SHA-256, 600,000회 반복과 사용자별 무작위 salt로 저장한다.
- 신규·변경 비밀번호는 12~256자 범위로 제한한다.
- 로그인 세션의 기본 만료 시간은 8시간이다.
- 세션 쿠키는 `Secure`, `HttpOnly`, `SameSite=Strict`로 설정한다.
- Manager는 인증된 요청마다 사용자를 DB에서 다시 조회해 삭제 여부, 활성 상태, 기업 운영 상태와 현재 역할을 확인한다.
- 세션에는 비밀번호 hash에 연결된 credential tag가 포함된다. 비밀번호가 변경되면 기존 세션은 더 이상 유효하지 않다.
- 모든 HTML 변경 요청은 세션 인증과 CSRF 검사를 함께 수행한다.
- 자기 비밀번호 변경이 완료되면 현재 세션을 종료하고 다시 로그인하도록 한다.

## 감사 기록

현재 다음 사용자 작업의 성공 결과를 관리자 감사 로그에 기록한다.

- 최초 시스템 관리자 생성
- 기업 사용자·관리자 생성
- 역할·활성 상태·표시 이름·비밀번호 변경
- 사용자 soft delete
- 자기 비밀번호 변경
- CLI 시스템 관리자 비밀번호 복구

실패하거나 권한 검사에서 차단된 모든 사용자 관리 요청을 감사 로그에 남기는 기능은 아직 일관되게 적용되지 않았다.

## 현재 제약과 개선 후보

1. `기업 사용자`는 실제 운영 권한을 가지므로 화면 표시 명칭을 `기업 운영자`로 바꾸는 방안을 검토한다. DB 역할값은 호환성을 위해 유지할 수 있다.
2. 공식적인 다중 시스템 관리자 생성·비활성화·복구 흐름과 마지막 시스템 관리자 보호가 필요하다.
3. 내부 `M-WAF 시스템 운영` 기업을 일반 고객 기업 선택 목록에서 더 명확히 구분할 필요가 있다.
4. 사용자 관리 실패와 권한 차단 결과까지 감사 로그 범위를 확대할 필요가 있다.
5. 모니터링만 필요한 조직을 위해 별도의 읽기 전용 역할이 필요한지는 실제 운영 요구가 생길 때 결정한다.

위 개선 후보는 현재 구현 범위에 포함되지 않는다.

## 구현 기준 위치

- 역할과 비밀번호 처리: `internal/manager/identity.go`
- 세션과 기업 범위: `internal/manager/session.go`
- 계정 저장·마지막 관리자 보호: `internal/manager/store_identity.go`
- 사용자 관리 화면 처리: `internal/manager/admin_identity_handlers.go`
- 관리자 라우트 권한: `internal/manager/routes_admin.go`
- 사용자 관리 화면: `web/templates/users.html`, `web/templates/user-edit.html`

## 2026-08-08 로컬 개발 DB 확인 기록

읽기 전용 확인 시점의 로컬 개발 DB에는 활성 시스템 관리자 1명과 활성 내부 운영 기업 1개가 있으며, 기업 관리자와 기업 사용자는 아직 등록되지 않았다. 이 값은 제품 기본값이 아니라 해당 개발 DB의 시점별 상태다.
