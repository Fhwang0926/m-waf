# M-WAF 제어·정책 운영 기능 보완

## 완료 범위

- Agent의 기존 주기적 HTTPS 폴링 구조를 유지했다. WebSocket이나 상시 명령 채널은 추가하지 않았다.
- Manager가 예약할 수 있는 원격 동작을 Agent 재시작/중지, 서버 재시작/종료 네 가지 고정 명령으로 제한했다.
- 임의 셸 문자열은 API와 UI 어디에서도 받지 않으며 Agent는 고정된 `systemctl --no-block` 인자만 실행한다.
- 서버 등록 해제 시 서버·이벤트 이력은 보존하고 `revoked_at` 상태와 Agent 인증서 검증을 통해 이후 Agent API 접근을 차단한다.
- 서명된 bundle catalog의 현재 호환 패키지 강제 업데이트와 manifest의 `rollback_id`로 지정된 Agent·모듈 쌍 롤백을 추가했다.
- 패키지는 Agent가 HTTPS로 내려받아 크기와 SHA-256을 확인한 뒤 APT로 설치하고 결과를 Manager에 보고한다.
- 기업 범위 서버 그룹의 생성·구성 변경·삭제와 그룹 대상 일괄 정책 배포를 추가했다.
- 정책 이름/설명, 탐지·차단 모드, CRS 민감도, 차단 임계점수, 요청 본문 검사, URL/IP 예외, 제한된 사용자 정의 `SecRule`을 지원한다.
- 사용자 정의 규칙은 한 줄짜리 `SecRule`, 고유 ID `100000..199999`만 허용하고 외부 실행·파일 검사 계열 동작을 거부한다.
- 정책 개정본별 대기/적용/실패 수와 서버별 정책·패키지·고정 명령 상태를 관리자 화면에 표시한다.
- 기업 사용자/관리자의 표시 이름, 권한, 비밀번호, 활성 상태 수정과 감사 이력을 보존하는 소프트 삭제를 추가했다.

## 권한 경계

- 시스템 관리자는 모든 기업의 서버, 그룹, 정책, 패키지, 사용자 작업을 수행한다.
- 기업 관리자는 자기 기업의 서버와 그룹만 제어하며 기업 사용자의 계정만 수정·비활성화·삭제한다.
- 기업 사용자는 기존과 같이 자기 기업의 서버와 이벤트만 조회한다.
- 시스템 관리자 계정은 하위 사용자 관리 화면에서 수정하거나 삭제할 수 없도록 유지했다.

## 인증서 사용 이유

Agent 인증서는 등록된 서버 한 대의 암호학적 신원을 나타낸다. Manager는 mTLS로 상태·이벤트의 발신 서버를 확인하고 해당 서버에 허용된 정책과 패키지만 반환한다. 등록 해제는 CA 전체나 다른 Agent에 영향을 주지 않고 해당 서버 ID의 인증서 접근만 거부한다.

## 데이터 변경

- 전진형 migration `004_control_plane_operations.sql`에 인증서 폐기 상태, 사용자 소프트 삭제, 정책/패키지 배포 상태, 서버 그룹, 고정 명령 큐를 추가했다.
- 기존 MariaDB에 migration을 실행하거나 데이터를 초기화·재설정하지 않았다.

## 확인 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- `git diff --check`로 공백 오류가 없음을 확인했다.
- 저장소 지침에 따라 Go/프론트엔드 빌드, 자동 테스트, 브라우저 실행, DB migration 적용은 수행하지 않았다.
- 실제 Agent의 APT 업데이트·롤백과 재시작/종료 명령은 Ubuntu 24.04 systemd 테스트 서버에서 별도로 확인해야 한다.
