# M-WAF CRS 검색 도구막대 UX 개선

## 문제

CRS 관리 화면의 검색 폼이 1100px 이하에서 두 열 폼으로 강제 전환되어 `정책 연결`과 검색 버튼이 여러 행으로 분리되고, 목록보다 검색 영역이 과도하게 커졌다. `전체` 옵션과 항상 표시되는 초기화 버튼도 각 조건의 의미와 현재 적용 상태를 빠르게 파악하기 어려웠다.

## 반영 내용

- CRS 검색어, 채널, 정책 연결, 검색 동작을 데스크톱과 태블릿에서 한 행에 배치했다.
- 검색어 입력은 가장 넓게, 채널과 정책 연결은 내용에 맞는 고정 최소 폭으로 구성했다.
- 입력 명칭을 `CRS 검색`, `정책 연결`로 간결하게 정리했다.
- 옵션을 `전체 채널`, `전체 연결 상태`로 변경해 선택 상자만 봐도 범위를 알 수 있게 했다.
- 검색어 예시를 `버전·태그·commit 검색`으로 축약하고 최대 255자를 명시했다.
- `조회`를 일반적인 검색 동작인 `검색`으로 변경했다.
- 초기화 동작은 검색 조건이 있을 때만 `조건 지우기` 텍스트 동작으로 표시한다.
- 760px 이하에서는 기존 반응형 규칙을 따라 필드와 동작을 한 열로 배치한다.
- 기존 GET URL과 `q`, `channel`, `link_status` query 계약은 변경하지 않았다.

## 확인 범위

- Go 템플릿 파싱, CSS 중괄호 균형과 `git diff --check`를 정적으로 확인했다.

## 수행하지 않은 검증

- 저장소 지침에 따라 프론트엔드 빌드와 자동 테스트는 실행하지 않았다.
- 로그인 후 브라우저에서 실제 1060px·760px·390px 렌더링은 확인하지 않았다.
- DB, CRS 동기화와 시스템 정책 데이터는 변경하지 않았다.
