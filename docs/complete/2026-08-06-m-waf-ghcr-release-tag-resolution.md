# M-WAF GHCR 릴리스 태그 판별 수정 완료

## 문제

- GHCR의 `m-waf-manager` 패키지 API는 응답했지만 `latest` manifest가 없어 태그 릴리스가 중단됐다.
- 기존 workflow는 패키지 API의 HTTP 200만으로 이전 정식 릴리스가 존재한다고 판단했다.
- 실패한 게시 시도가 남긴 패키지 객체, 태그 없는 버전 또는 현재 버전만 존재해도 최초 성공 릴리스를 만들 수 없었다.

## 수정

- GitHub Packages API 응답의 `metadata.container.tags`에서 정식 `x.y.z` 태그만 추출한다.
- 현재 릴리스보다 낮은 가장 높은 정식 태그를 N-1 롤백 원본으로 선택한다.
- 선택한 고정 버전 이미지를 pull하고 기존 서명 번들 검증을 통과한 경우에만 롤백 패키지를 결합한다.
- 이전 정식 태그가 없고 현재 태그 또는 태그 없는 흔적만 있으면 최초 릴리스의 5개 패키지 번들을 생성한다.
- 현재보다 높은 정식 태그가 있거나, 이전 이미지 pull·서명 검증·API 조회가 실패하면 릴리스를 중단한다.
- 이동 가능한 `latest` 태그는 게시 편의 태그로만 유지하고 롤백 원본 판별에는 사용하지 않는다.
- 검증된 `vMAJOR.MINOR.PATCH` Git 태그 릴리스가 이미지를 게시할 때 같은 digest에 `latest`도 명시적으로 추가한다.

## 확인 범위

- GitHub Actions YAML 파싱과 `Sign embedded package bundle` 셸 구문을 확인했다.
- 최초 릴리스, 현재 태그 재시도, 복수 이전 버전, 두 자리 patch 버전 및 역순 릴리스 판별을 정적으로 확인했다.
- `git diff --check`를 확인했다.
- 실제 GHCR push와 태그 workflow 재실행은 로컬에서 수행하지 않았다.
- GitHub CLI 인증 토큰이 만료되어 원격 run 재조회는 수행하지 못했으며 사용자 제공 로그를 실패 증적으로 사용했다.
- 프론트엔드 빌드와 테스트, DB 작업은 수행하지 않았다.
