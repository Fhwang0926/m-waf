# 기업 안전 삭제 및 운영 종료 완료

## 변경 목적

시스템 관리자가 잘못 생성한 빈 기업은 삭제하고, 서버·사용자·정책·토큰 등 운영 이력이 있는 기업은 보안 및 감사 이력을 훼손하지 않고 운영 종료할 수 있도록 기업 생명주기를 추가했다.

## 동작

- 사용자, 서버, 정책·revision, 서버 그룹, 등록 토큰, 기업 설치 토큰이 모두 없는 기업은 MariaDB에서 실제 삭제한다.
- 연결 데이터가 하나라도 있으면 기업 상태를 `TERMINATED`로 변경하고 이력은 유지한다.
- 운영 종료 transaction은 기업 사용자를 비활성화하고, 기업 설치 토큰과 미사용 등록 토큰을 폐기하며, 모든 보호 서버를 `REVOKED`로 변경한다.
- 대기·진행 중인 정책 rollout, Agent 명령, 정책 및 패키지 배포는 운영 종료 시 함께 취소 또는 종결한다.
- 백그라운드 정책 처리기는 운영 중인 기업의 rollout만 선택한다. 정책 개정·할당·완료 transaction도 기업 상태를 잠가 종료 처리와 직렬화하며, 이미 취소된 rollout 상태를 덮어쓰지 않는다.
- 종료 기업의 기존 Agent 인증서는 즉시 Agent API 인증에서 거부된다.
- 종료 기업 사용자는 신규 로그인과 기존 세션 사용이 모두 차단된다.
- 활성 기업 조회만 사용자, 그룹, 서버 등록과 설치 토큰 생성 대상에 사용한다.
- 기업 관리 화면은 상태와 연결 데이터 수를 표시하고, 정확한 기업명 확인 후 `기업 삭제` 또는 `기업 운영 종료`를 실행한다.
- 종료 기업은 기업 관리 화면에 남아 종료 시각과 보존된 연결 데이터 규모를 확인할 수 있다.

## 데이터베이스 변경

- `enterprises.status`
- `enterprises.terminated_at`
- `enterprises.terminated_by`
- 상태·이름 조회 index와 종료 처리자 외래키

Migration은 순방향 파일로만 추가했으며 실제 운영 DB에는 실행하지 않았다.

## 검증 범위

- 기업 상태와 완전 삭제 가능 여부의 단위 테스트 소스를 추가했다.
- 변경한 Go 파일에 `gofmt`를 적용했다.
- shell 문법과 `git diff --check`를 확인했다.
- 저장소 작업 지침에 따라 Go test, 프론트엔드 빌드, Docker E2E와 실제 MariaDB migration은 실행하지 않았다.
