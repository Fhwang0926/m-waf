# 미사용 시스템 정책 회수·동일 CRS 재게시

## 완료 내용

- 기업 정책이 사용하지 않고 진행 중인 rollout이 없는 시스템 정책은 `PUBLISHED` 또는 `DEPRECATED` 상태에서 회수할 수 있게 했다.
- 현재 게시본도 미사용 상태라면 시스템 정책 화면에서 확인 체크 후 회수할 수 있다.
- 회수된 정책은 DB에서 삭제하지 않고 불변 이력과 감사 기록을 유지한다.
- 회수 후 게시된 시스템 정책이 없으면 같은 CRS 원본으로 새 시스템 정책을 다시 게시할 수 있다.
- 동일 CRS 재게시는 기존 정책 ID와 버전을 재사용하지 않고, 과거의 회수·이전 개정본을 포함한 다음 미사용 patch 번호를 발급한다.
  - 예: `crs-baseline@1.0.0` 회수 후 같은 CRS 재게시 → `crs-baseline@1.0.1`
- 게시 트랜잭션에서도 다음 개정본 번호를 다시 검사해 동시 게시와 기존 불변 버전 충돌을 차단한다.
- 시스템 정책 이력의 CRS 버전 중복 제거를 없애 같은 CRS로 게시한 모든 정책 개정본을 표시한다.
- 회수 불가 시 사용 기업 또는 진행 중인 rollout을 이유로 표시하고, 실패 응답을 성공 알림으로 표시하던 동작을 오류 알림으로 분리했다.
- 게시된 정책이 없는 경우 회수 이력에서 `같은 CRS 재게시` 경로를 제공한다.

## 안전 조건

- 시스템 관리자 RBAC, CSRF와 확인 체크박스를 유지한다.
- 기업 정책이 하나라도 현재 시스템 정책을 참조하면 회수를 차단한다.
- `AWAITING_APPROVAL`, `QUEUED`, `CANARY`, `EXPANDING`, `PAUSED` rollout이 있으면 회수를 차단한다.
- 회수된 시스템 정책을 대상으로 하는 신규 적용과 롤백 차단은 기존 동작을 유지한다.

## 호환성

- DB schema와 migration은 변경하지 않았다.
- 기존 시스템 정책·기업 정책·개정본·rollout 레코드는 수정하거나 삭제하지 않았다.
- 기존 `/system-policies/{id}/withdraw` URL과 감사 이벤트 이름을 유지한다.
- 동일한 OWASP CRS 버전을 다시 사용할 수 있지만 시스템 정책 개정본 ID는 항상 새로 생성한다.

## 검증 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- Go 템플릿 파싱, Go 패키지·테스트 소스 로딩, CSS 괄호와 `git diff --check`를 정적으로 확인했다.
- 저장소 지침에 따라 자동 테스트, 프론트엔드 빌드, 브라우저 실행, DB migration·초기화·reset과 실제 정책 회수·재게시를 수행하지 않는다.
