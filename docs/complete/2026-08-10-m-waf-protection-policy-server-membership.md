# M-WAF 보호 정책 중심 서버 그룹화 완료

## 반영 범위

- 보호 정책을 서버 그룹의 단일 기준으로 변경했다.
  - 한 보호 정책에 같은 기업의 여러 서버를 연결할 수 있다.
  - 서버는 `enterprise_policy_servers.server_id` 기본 키로 최대 한 정책에만 연결된다.
  - 신규 등록 서버는 보호 정책을 자동 배정하지 않고 `미배정`으로 유지한다.
- 보호 정책 생성 계약을 기존 `target`에서 `server_ids`로 변경했다.
  - 같은 기업의 활성 서버를 한 대 이상 요구한다.
  - 요청의 시스템 정책 선택값을 사용하지 않고 생성 시점의 현재 게시 시스템 정책을 Manager가 직접 상속한다.
  - 정확한 시스템 정책 버전 ID를 서명된 불변 정책 개정본에 기록한다.
- 서버 추가·이동 경로 `POST /policies/{id}/servers`를 추가했다.
  - 대상 정책 적용이 성공한 서버만 관계를 변경한다.
  - 기존 정책 관계는 적용 성공 전까지 유지한다.
  - 실패 시 서버별 `source_revision_id`와 패키지 스냅샷을 사용하고, 원본 정책·개정본별 복구 rollout으로 기존 상태를 정확히 복구한다.
  - 진행 중인 배포 대상 서버의 이동은 차단하고, 같은 정책 재선택은 작업 없이 종료한다.
  - 별도 미배정 전환 경로는 제공하지 않는다.
- 정책에 연결된 서버가 없어져도 정책과 개정본, 배포 이력은 삭제하지 않는다.
- 시스템 정책 업데이트·수동 승인·자동 배포·고정·롤백·동기화의 대상 계산을 현재 정책 관계 서버로 통일했다.
  - 기존 자동 기본 정책 생성과 `enterprise:`, `group:`, `server:` 우선순위 재조정 실행 코드를 제거했다.
  - 기존 대상 문자열과 서버 그룹 데이터는 이전·감사용으로 보존한다.
- 신규 서버 등록 시 패키지 선택 여부와 관계없이 빈 desired state를 생성한다.
  - 최초 설치에는 `DetectionOnly` 안전 placeholder를 준비한다.
  - 이후 정책 연결 시 기존 서명 정책 적용, 웹서버 configtest와 reload 절차를 사용한다.
- 보호 정책 생성·상세·목록과 서버 목록·상세·기업 상세 화면을 현재 정책 관계 중심으로 변경했다.
  - 생성 화면은 다중 서버와 각 서버의 현재 정책을 보여준다.
  - 정책 상세는 연결 서버, 미배정 서버 추가, 다른 정책에서 이동, 진행 중 배포 상태를 보여준다.
  - 기존 서버 그룹 화면과 쓰기 코드를 제거하고 기존 조회 URL은 보호 정책 목록으로 연결한다.
  - 관제·서버·이벤트 필터는 `policy_id`를 사용하고 이벤트 이력은 이벤트에 기록된 정책 개정본 기준으로 조회한다.

## 마이그레이션

- `migrations/014_protection_policy_membership.sql`을 추가했다.
  - 기존 활성 정책의 대상 우선순위 `server > group > enterprise`와 최신 변경 시각을 사용해 서버별 단일 관계를 만든다.
  - 서버 그룹과 대상 데이터는 삭제하거나 변경하지 않는다.
  - 기존 rollout 대상은 가능한 현재 개정본으로 `source_revision_id`를 보강하고, 이후 rollout은 생성 시점의 서버별 원본 개정본을 저장한다.
- 마이그레이션 파일만 작성했으며 실제 DB에는 적용하지 않았다.
- DB 시각은 기존 원칙대로 UTC로 저장하고 화면에서는 KST로 변환해 표시한다.

## 정적 확인

- 관련 화면·API 계약과 마이그레이션 검증 테스트 코드를 갱신했다.
- 컨테이너 E2E 시나리오의 서버 그룹 생성 단계를 제거하고 보호 정책 생성 시 두 서버 ID를 직접 전달하도록 갱신했다.
- Go 소스와 테스트 파일에 `gofmt`를 적용했다.
- `git diff --check`로 공백 오류를 확인했다.

## 수행하지 않은 검증

- 지침에 따라 Go 테스트와 프론트엔드 빌드를 실행하지 않았다.
- DB init, reset, 마이그레이션 적용 또는 데이터 변경을 수행하지 않았다.
- 실행 중인 Manager를 재빌드·재시작하지 않았고 인증 화면/API를 변경된 바이너리로 확인하지 않았다.
- 실제 Agent의 Apache/Nginx configtest, reload, 정책 이동 성공·실패·복구는 수행하지 않았다.
