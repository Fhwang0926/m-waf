# 기업 설치 토큰 사용 범위 제한 완료

## 변경 목적

- 기업 설치 토큰을 서버 설치와 탐지 로그 수신 검증에만 사용한다.
- 정책, 패키지, 명령, heartbeat와 인증서 API에는 설치 토큰이 전달되거나 사용되지 않도록 분리한다.
- 탐지 로그는 기존 Agent mTLS 신원 확인과 설치 토큰의 기업 범위 확인을 모두 통과해야 수신한다.

## 반영 내용

- 설치기가 입력받은 기업 설치 토큰을 `/etc/mwaf-agent/event-verification.token`에 권한 `0600`으로 저장한다.
- Agent는 `POST /agent/v1/events/batch` 요청에만 `X-MWAF-Event-Token` 헤더를 추가한다.
- Manager는 mTLS로 확인한 서버와 토큰이 같은 기업에 속하는지 확인한 뒤 이벤트 배치를 처리한다.
- 다른 Agent API는 기존 mTLS 인증만 사용하며 설치 토큰 헤더를 읽지 않는다.
- 설치 토큰 폐기는 신규 설치 범위만 차단한다. 이미 등록된 Agent가 보관한 과거 토큰은 같은 기업의 탐지 로그 검증에만 계속 사용할 수 있다.
- 기존 단일 서버용 등록 토큰 설치 흐름은 사용 완료된 등록 토큰을 동일한 이벤트 검증 파일에 보관하는 호환 경로를 유지한다.
- DB 스키마와 공개 이벤트 payload는 변경하지 않았다.

## 배포 주의

- 기존 Agent 설정에 `event_verification_token_file`이 없으면 변경된 Manager가 이벤트 배치를 `401`로 거부한다.
- Manager만 먼저 반영하지 말고, 기존 Agent에 기업 토큰 파일과 설정을 안전하게 배포한 뒤 Manager와 Agent 변경을 함께 전환해야 한다.
- 토큰 파일이나 헤더 값을 로그, 명령행 인자 또는 일반 권한 설정 파일에 남기면 안 된다.

## 확인 내용

- 변경한 Go 파일에 `gofmt`를 적용했다.
- 저장소 전체 변경의 공백 및 패치 형식을 `git diff --check`로 확인했다.

## 수행하지 않은 검증

- 저장소 지침에 따라 빌드와 자동 테스트는 실행하지 않았다.
- DB init, reset, migration과 직접 데이터 쓰기는 수행하지 않았다.
- 현재 실행 중인 Manager와 실제 Agent에는 변경 바이너리·설정이 반영되지 않아 탐지 로그 수신은 확인하지 않았다.
