# 기업별 재사용 설치 토큰 및 설치 화면 단순화 완료

## 변경 목적

- 기업마다 하나의 활성 설치 토큰을 발급하고, 운영자가 폐기하기 전까지 여러 서버 설치에 계속 사용한다.
- 고객 웹서버 설치 화면에는 실제 설치에 필요한 환경, 토큰, 실행 명령만 우선 표시한다.
- 서버별 등록 세션과 mTLS 인증서 발급 구조는 그대로 유지한다.

## 반영 내용

### 기업 설치 토큰

- 웹 관리자 화면에서 생성하는 토큰은 만료일과 등록 횟수 제한 없이 폐기 전까지 사용할 수 있다.
- 기업별 활성 토큰이 이미 있으면 추가 생성을 차단하고 기존 토큰 재사용 또는 폐기 후 재발급을 안내한다.
- 토큰 원문은 생성 직후 한 번만 표시한다. Manager에는 해시와 식별 접두어만 저장하므로 원문을 분실하면 기존 토큰을 폐기하고 새로 발급해야 한다.
- 기존 DB 열을 유지하고 영구 토큰 식별용 저장 마커를 사용했다. DB 마이그레이션과 Agent 프로토콜 변경은 없다.
- 기존 만료형 토큰은 기존 만료일과 등록 횟수 제한을 그대로 적용한다.
- 기존 API 호환성을 위해 API 토큰 생성은 기본 30일 동작을 유지한다. API에서 폐기 전까지 사용할 토큰을 만들 때는 `persistent: true`를 명시한다.
- 영구 토큰으로 설치할 때도 설치기는 서버마다 짧은 등록 세션을 발급받으며, 등록된 Agent는 개별 mTLS 인증서로 동작한다.

### 설치 화면

- 설치 대상 기업 선택을 상단의 간단한 선택 영역으로 정리했다.
- 지원 환경은 다음 세 항목만 우선 표시한다.
  - Ubuntu Server 24.04 LTS, amd64
  - Apache 또는 Nginx
  - M-WAF Agent와 ModSecurity 통합 모듈
- 일반 설치 흐름은 토큰 생성, 토큰 보관, 명령 복사 순서로 축소했다.
- 활성 토큰이 있으면 토큰 접두어, 등록 서버 수, 마지막 사용 시각과 재사용 설치 명령을 표시한다.
- 커스텀 빌드 Apache/Nginx용 외부 Connector 연결 명령은 접힌 상세 영역으로 유지했다.
- 토큰 이력과 폐기 작업은 접힌 관리 영역으로 이동했다.
- 기존 스타일과 템플릿 구조를 재사용했으며 새 프론트엔드 라이브러리는 추가하지 않았다.

## 확인 내용

- Go 변경 파일에 `gofmt`를 적용했다.
- 변경 파일의 공백 및 패치 형식을 `git diff --check`로 확인했다.
- 현재 실행 중인 Manager가 `127.0.0.1:8443`에서 수신 중인 것을 확인했다.
- 현재 Manager의 인증된 `/enrollments/new` 화면에서 기업 선택, 설치 환경 표, 기업 설치 토큰 생성 영역이 노출되는 것을 확인했다.
- 화면 확인 과정에서 토큰 생성 버튼은 누르지 않았으며 DB 데이터는 변경하지 않았다.

## 수행하지 않은 검증

- 저장소 지침에 따라 프론트엔드 빌드와 자동 테스트는 실행하지 않았다.
- DB init, reset, migration과 직접 데이터 쓰기는 수행하지 않았다.
- 실제 토큰 생성, 고객 서버 패키지 설치, Agent 자동 등록의 종단 간 시험은 수행하지 않았다.
