# M-WAF 탐지 이벤트 조회 확장성 개선

## 완료 범위

- 이벤트 목록 정렬을 `occurred_at DESC, id DESC`로 고정했다.
- 관리자 HTML 이벤트 목록의 다음·이전 이동을 `(occurred_at, id)` 기반 cursor 조회로 변경했다.
- 같은 마이크로초의 이벤트도 ID 보조 키로 중복·누락 없이 이동하도록 했다.
- 필터 변경 시 기존 page와 cursor를 제거해 첫 페이지부터 다시 조회하도록 했다.
- Admin JSON API는 기존 page·page_size·응답 필드를 유지하고 cursor 입력과 이전·다음 cursor 응답을 추가했다.
- 기존 API 호출은 cursor가 없을 때 종전 OFFSET 방식으로 동작한다.
- 대시보드의 동일 기간·기업·그룹·서버 집계 결과를 Manager 인스턴스에서 15초간 재사용한다.
- cache 항목을 128개로 제한하고 만료 정리를 적용했다.
- 기존 MariaDB 인덱스를 사용하며 새 DB migration이나 외부 저장소를 추가하지 않았다.
- 현재 구조의 비용이 큰 조회, 운영 측정 지표와 2차 개선·별도 이벤트 저장소 도입 기준을 문서화했다.

## 호환성과 안전

- Agent 이벤트 수신 API, event 원본 형식과 중복 방지는 변경하지 않았다.
- 기업 범위는 cursor와 무관하게 각 요청에서 다시 검사한다.
- cache는 조회 결과에만 사용하며 정책 판단과 원본 저장에는 사용하지 않는다.
- DB migration, 데이터 backfill, init/reset과 외부 저장소 도입은 수행하지 않았다.

## 확인 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- 실행 중인 개발 감시기가 Manager를 자동 재빌드했으며 8443 listener가 새 PID로 재기동된 것을 확인했다.
- cursor round-trip과 앞·뒤 페이지 경계를 다루는 단위 테스트를 추가했지만 실행하지 않았다.
- 전체 Go 테스트, 프론트엔드 빌드와 브라우저 실행은 저장소 지침에 따라 수행하지 않았다.
