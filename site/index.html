WAF 운영은 중앙에서.

Apache·Nginx 프로세스에서 요청을 검사하고, 정책 배포와 서버 상태, ModSecurity 보안 이벤트는 별도 Manager에서 관리합니다.

DIFFERENTIATION

호스팅 환경의 변경 범위는 줄이고
운영 경계는 분명하게.

검증된 오픈소스 구성요소를 다시 만들지 않고 조합합니다. 중앙 프록시를 추가하지 않아 고객 트래픽 경로와 기존 웹 애플리케이션 구성을 유지합니다.

01

인라인 장비 없는 로컬 검사

클라이언트 요청은 Manager를 거치지 않습니다. Apache·Nginx에 연결된 ModSecurity가 웹서버에서 직접 검사하고 차단합니다.

02

고객 서버 설치는 두 패키지

공통 mwaf-agent와 웹서버별 통합 패키지만 설치합니다. 배포판 웹서버와 운영자가 관리하는 커스텀 빌드를 구분해 적용합니다.

03

오픈소스 기반의 자체 운영

OWASP CRS·ModSecurity를 기반으로 Manager와 MariaDB를 호스팅사 인프라에 둡니다. 기업별 정책과 여러 서버의 상태·이벤트를 한 곳에서 관리합니다.

SECURITY POLICY

검증된 CRS를 기준으로
기업별 보호 수준을 운영합니다.

CRS 소스를 가져오는 단계와 실제 정책을 게시하는 단계를 분리합니다. 검토한 시스템 정책을 기준으로 기업별 탐지·차단 설정과 예외만 관리합니다.

01

검증된 기준 정책

OWASP CRS 4.28.0의 버전·커밋·아카이브 해시를 확인하고, 관리자가 검토한 뒤 수정 불가능한 새 시스템 정책 버전으로 게시합니다.

02

보호 수준 설정

탐지만 또는 탐지·차단, Paranoia Level, Inbound 차단 점수와 요청 본문 검사를 기업 정책으로 설정합니다.

03

서비스 예외 관리

URL, IP/CIDR, Rule ID·Target 예외와 제한된 추가 SecRule을 검증한 뒤 서명된 정책 리비전으로 생성합니다.

04

통제된 배포와 복구

자동·수동 승인·버전 고정 전략을 선택하고, 카나리·확대 배포와 웹서버 설정 검사 후 문제가 생기면 직전 성공 버전으로 롤백합니다.

ARCHITECTURE & RUNTIME

요청 검사는 고객 서버에서,
정책과 로그는 Manager에서.

웹 요청 경로와 관리 경로를 분리합니다. Agent는 Manager로 발신 연결해 정책을 주기적으로 확인하고 감사 로그를 전송하며, Manager가 일시 중단돼도 웹서버는 마지막 성공 정책으로 계속 동작합니다.

SERVER ENROLLMENT

기업 설치 토큰 하나로
서버를 자동 등록합니다.

서버를 Manager에 미리 생성하지 않습니다. 설치 토큰과 검토한 스크립트를 고객 서버에 전달하면 환경 진단, 패키지 선택, 서버 등록과 Agent 인증서 발급이 이어집니다.

  1. 1
    Manager에서 기업 설치 토큰 생성유효기간과 선택적인 등록 한도 설정
  2. 2
    고객 서버에서 설치 스크립트 검토·실행CA로 Manager를 검증하고 토큰은 숨김 입력
  3. 3
    서버 자동등록 후 mTLS 전환재사용 토큰은 Agent 설정에 저장하지 않음

WEB SERVER & WAS SUPPORT

직접 지원 웹서버와
WAS 연동 범위를 구분합니다.

모듈 설치와 버전 검증의 대상은 Apache·Nginx입니다. WAS는 두 웹서버 뒤에서 HTTP(S)로 연결되는 애플리케이션 계층이며, M-WAF 모듈을 WAS에 직접 설치하지 않습니다.

지원 판정 기준

WAS가 표에 없어도 요청이 지원 Apache/Nginx를 반드시 통과하면 보호할 수 있습니다. 이는 해당 WAS에 대한 직접 설치 지원이나 제품별 호환성 인증을 뜻하지 않습니다.

현재 지원하지 않음

RPM 계열, ARM64, Windows, IIS, OpenResty, portable Agent, Connector 자동 컴파일, WAS 직접 설치, Manager HA와 공식 처리량 보증.

버전 명세 확인
OPEN-SOURCE WAF REVIEW공개 오픈소스 WAF 프로젝트와 운영 모델 비교

M-WAF는 새로운 탐지 엔진을 만드는 프로젝트가 아닙니다. ModSecurity와 OWASP CRS를 고객 웹서버에 적용하고, 호스팅사가 여러 서버의 정책·상태·이벤트를 자체 Manager에서 운영하도록 관리 계층을 더한 MVP입니다.

프로젝트검사·배치 방식정책 기반다중 서버 운영M-WAF와의 차이
M-WAF MVP기존 Apache·Nginx 프로세스에서 검사검증된 CRS 4.28.0 + 기업별 탐지·차단·예외 정책Agent·Manager, 기업 격리, 단계 배포와 이벤트 수집기존 웹서버를 유지하는 호스팅 서버군 운영에 집중
ModSecurity + OWASP CRSApache 모듈 또는 웹서버 Connector로 직접 내장SecLang과 CRS 파일을 운영자가 직접 구성엔진·규칙 프로젝트 외의 관리 체계는 별도 구축M-WAF가 그대로 사용하는 검사 엔진과 기본 규칙
BunkerWebNGINX 기반 WAF를 리버스 프록시로 배치내장 ModSecurity·CRS와 설정·사용자 구성Web UI, Scheduler, DB와 다중 서비스 구성 제공기존 웹서버 모듈이 아니라 보호 프록시 계층을 추가
CorazaGo 애플리케이션 또는 지원 Connector에 내장ModSecurity SecLang과 OWASP CRS v4 호환라이브러리 중심이며 운영 계층은 연동 프로젝트가 담당대체 가능한 Go WAF 엔진으로, 현재 M-WAF에는 포함하지 않음
