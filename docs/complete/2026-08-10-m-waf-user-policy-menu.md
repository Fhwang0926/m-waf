# 사용자 정책 메뉴 분리 완료

## 변경 내용

- 정책 메뉴를 `보호 정책`과 `사용자 정책`으로 분리했다.
  - 보호 정책은 서버 연결, 공통 보호 설정, 단계 배포와 변경 이력을 관리한다.
  - 사용자 정책은 보호 정책에 추가되는 탐지 예외, IP·CIDR 정책, 사용자 Rule을 관리한다.
- `/user-policies`에 보호 정책·종류·검색 필터와 항목별 현황을 추가했다.
- IP·CIDR 차단·신뢰와 안전한 안내형 사용자 Rule을 사용자 정책 화면에서 추가하고 제거할 수 있게 했다.
- 사용자 정책 변경은 기존 설정을 직접 수정하지 않고 새 서명 불변 개정본과 단계 배포를 생성한다.
- 보호 정책 상세의 기존 `예외·간편 규칙` 탭은 읽기 전용 `최종 적용 정책`으로 교체했다.
- 기존 `/ip-rules`와 `?tab=rules` 링크는 사용자 정책 화면으로 이동하도록 호환 처리했다.
- 보호 정책 변경 화면에서는 사용자 Rule 편집 영역을 제거하되 기존 Rule 값은 그대로 보존한다.

## 호환성

- 기존 예외·IP 정책 POST 경로, Agent API, 정책 artifact 형식과 DB 스키마는 변경하지 않았다.
- 역할 검사와 `ScopeEnterpriseID()` 기반 기업 범위 검사를 그대로 사용한다.
- 시스템 정책과 upstream CRS는 사용자 정책에서 수정할 수 없다.

## 검증

- 탐지 예외 만료·중복 검사, 사용자 Rule 표시, 기존 IP 정책 URL 이동, 보호 정책 탭과 역할별 메뉴 관련 Go 회귀 테스트를 통과했다.
- `go test -count=1 ./cmd/mwaf-manager`, `gofmt`, `git diff --check`를 통과했다.

## 수행하지 않은 검증

- 저장소 지침에 따라 프론트엔드 빌드와 프론트엔드 테스트는 수행하지 않았다.
- 전체 `internal/manager` 테스트는 현재 별도 서버 패키지 UI 작업의 기대 문구 2건이 맞지 않아 통과하지 않았다. 사용자 정책 관련 테스트는 분리해 통과했다.
- DB init, reset, migration 또는 실제 정책 생성·배포 같은 DB 쓰기 검증은 수행하지 않았다.
- 실제 Agent, Apache/Nginx 적용과 브라우저별 화면 확인은 수행하지 않았다.
