# M-WAF 실운영 관리자 UI/UX 개선 완료

## 완료 범위

- Go 서버 렌더링 구조를 유지한 240px 좌측 메뉴와 운영형 다크 콘솔 레이아웃 적용
  - 1024px 이하 축소 메뉴, 760px 이하 모바일 슬라이드 메뉴
  - 데스크톱·태블릿에서 메뉴 펼치기/접기와 브라우저별 선택 상태 기억
  - 축소 상태에서도 보이는 메뉴 경계 버튼으로 펼침·접힘 기능을 명확하게 제공하고 모바일에서는 상단 메뉴 버튼으로 전환
  - 축소 메뉴 하단의 상태점을 `정상` 텍스트와 함께 표시해 의미가 분명하도록 정리
  - 관제, 보호 정책, 인프라, 조직 관리, 시스템 관리 그룹
  - 현재 기업 범위, 사용자 권한, 마지막 갱신 시각, 수동 새로고침 표시
- `make dev` 실행 중 Go·템플릿·CSS·JavaScript 저장 시 Manager 자동 재빌드·재시작 및 열린 관리자 화면 자동 갱신
- 조치형 운영 대시보드와 `GET /api/v1/overview` 추가
  - 1시간, 24시간, 7일 및 기업, 그룹, 서버 필터
  - 탐지, 차단, 차단률, 온라인 서버, 실패 rollout, 승인 대기 요약
  - 이벤트 추이 인라인 SVG, 상위 Rule, URI, 서버, 최근 중요 이벤트
  - 오프라인, 장기간 미수신, 정책·패키지 실패, 승인 대기 조치 목록
  - 화면이 보일 때만 30초 API 폴링, 실패 시 기존 데이터 유지 및 갱신 지연 표시
- 보안 이벤트 관제 개선
  - 시간, 기업, 그룹, 서버, 처리 결과, 위험도, Rule ID, URL·메시지 필터
  - URL 필터 유지 및 개별 제거 칩
  - `GET /api/v1/events`의 기존 `items` 유지와 페이지 정보 추가
  - `GET /api/v1/events/{id}` 및 `?event=<id>` 직접 링크
  - 우측 상세 패널에서 동일 서버·`transaction_id` Rule 묶음, HTTP 상태, 정책 개정본, 서버·정책·예외 검토 이동 제공
- 정책 작성과 단계 배포 개선
  - 생성·편집 공통 5단계 작성 화면
  - 안내형 규칙을 안전한 SecRule로 생성하고 고급 SecRule을 함께 검증
  - 따옴표, phase, ID 범위, 중복 ID, 외부 실행·프록시·redirect·엔진 비활성화 동작 검증
  - `POST /api/v1/policies/validate`로 필드 오류와 영향 서버 제공
  - `GET /policies/{id}/edit`, `POST /policies/{id}/revisions` 추가
  - 기존 대상을 고정하고 `expected_revision_id` 일치 시에만 새 서명 불변 개정본과 즉시 rollout 생성
  - 정책 상세을 개요, 규칙·예외, 배포 현황, 개정 이력으로 구분하고 서버별 rollout 결과와 접힌 오류 원문 표시
- 서버·그룹·관리 화면 개선
  - 서버 카드 목록을 검색·필터 표로 변경하고 `/servers/{id}` 상세 추가
  - 서버 상세에서 상태, 정책, 패키지, 제어 이력과 재시작·중지·업데이트·롤백·등록 해제 위험 작업 분리
  - `/groups/{id}` 상세에서 구성원 연결 상태와 그룹 정책 rollout 상태 표시
  - 설치 화면에 토큰 생성, 설치 명령, Agent 연결, 정책 적용 진행 단계 표시
  - 시스템 관리자 전용 `/audit-logs` 화면과 시간, 수행자, 작업, 결과 필터 추가
  - 시스템 정책 화면을 버전 기본 설정·채택 범위·업데이트 및 실패 배포 조치 중심의 운영 화면으로 개편하고 기업 정책 생성·편집 흐름 연결
  - 시스템 관리자가 `/system-policies/new`에서 기존 게시본을 기반으로 보호 기본값, 공통 URL·IP 예외, 공통 SecRule과 마이그레이션 안내를 작성해 새 불변 버전으로 게시하도록 확장
  - 새 시스템 정책 버전 게시 시 같은 정책 계열의 기존 게시본을 사용 중단 예정으로 전환하고, 미사용 이전 버전만 명시적 확인 후 회수하도록 제한
  - 시스템 공통 Rule은 `240000..249999`, 기업 Rule은 `100000..199999`로 분리해 ID 충돌을 차단
  - 기업 정책 아티팩트 생성 시 시스템 공통 예외·Rule을 먼저 병합하고 기업별 예외·Rule은 별도 설정으로 보존
  - DB에 게시한 시스템 정책 버전을 기업 정책 생성, 검증, 업데이트, rollout, 롤백에서 동일하게 조회하도록 런타임 정책 참조를 DB 기준으로 연결
  - UUID와 내부 rollout·개정본 ID는 기본 화면에서 숨기고 상세 펼침 또는 복사로 제공

## 권한과 호환성

- 시스템 관리자는 전체 기업 또는 선택 기업을 조회한다.
- 기업 관리자와 기업 사용자는 기존 `ScopeEnterpriseID`로 소속 기업에 고정된다.
- 기업 사용자의 기존 정책·서버 운영 권한을 유지하고 사용자 관리는 기업 관리자 이상만 접근한다.
- 감사 로그는 기업 식별 정보가 없는 기존 데이터 특성상 시스템 관리자에게만 제공한다.
- 기존 Agent API, 포트, 인증서, DB 스키마 및 WebSocket 미사용 원칙은 변경하지 않았다.
- DB 마이그레이션과 신규 프론트엔드·차트 의존성을 추가하지 않았다.
- 영구 시스템 정책 초안은 추가하지 않았으며 게시 전 폼 검토 후 새 버전을 즉시 게시한다.

- `gofmt` 적용
- `git diff --check` 통과
- `node --check web/static/app.js` 통과
- `GOCACHE=/tmp/mwaf-go-build-cache go test ./...` 통과
- 전체 템플릿 파싱은 `internal/manager` 테스트에서 통과
- 실행 중인 로컬 Manager의 시스템 정책 운영 화면을 1024px 및 390px에서 확인하고 기준 버전별 기업 정책 필터 이동과 가로 넘침 없음 확인
- 시스템 정책 관리 추가분은 `go build -o /tmp/mwaf-manager-check ./cmd/mwaf-manager` 컴파일 확인 및 `git diff --check` 통과

## 미확인 항목

- 저장소 규칙에 따라 프론트엔드 빌드는 실행하지 않았다.
- 로컬 `18443` 포트에 실행 중인 Manager가 없어 로그인한 실제 화면과 1440px, 1024px, 760px, 390px 시각 검증은 수행하지 않았다.
- 시스템 정책 새 버전 게시·회수는 데이터 변경 작업이므로 현재 개발 DB에서 실행 검증하지 않았다.
- 실제 MariaDB 데이터가 연결된 환경에서 overview 집계, 이벤트 트랜잭션 묶음, 정책 동시 수정 충돌, rollout 서버별 결과는 통합 검증이 필요하다.
