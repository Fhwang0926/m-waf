# M-WAF 시스템 업데이트 화면 UX 단순화

## 작업 목적

시스템 관리자가 `/system-policies`에서 CRS 내부 구조와 배포 메타데이터를 한꺼번에 읽지 않고, 현재 보호 기준과 다음 운영 작업을 먼저 판단할 수 있도록 화면 정보 구조를 축소했다.

## 반영 내용

- 화면 제목을 `시스템 오버라이드`에서 내비게이션과 같은 `시스템 업데이트`로 통일했다.
- 항상 표시하던 4단계 수명주기와 CRS 원본 안내 경고를 제거했다.
- 현재 기본 보호 기준은 CRS 버전, 채널, 기본 동작, 적용 범위와 게시일만 한 패널에 표시한다.
- Paranoia Level, 임계점수, 예외·Rule·Setup 수, artifact, 내부 ID, commit과 digest는 접힌 `기술 정보`로 이동했다.
- 업데이트, 기업 정책 검토, 단계 배포 상태를 세 개의 운영 지표로 축소했다.
- 조치가 필요한 기업 정책은 최대 100개 목록 대신 전체 건수와 정책 화면 이동 버튼만 표시한다.
- 기본 보호 기준에서 `기업 정책 생성`을 제거하고 기업 정책 작성은 기존 보호 설정 화면에 유지했다.
- 현재 기준 이외의 CRS는 기본적으로 접힌 버전 이력 표에 표시하고, 이력이 많거나 검색 조건이 있을 때만 검색 폼을 표시한다.
- 이전 기준 회수, 기업 적용 현황, 다른 게시 채널의 기준 수정 경로는 버전 이력에서 계속 제공한다.
- 기존 `/system-policies` URL, migration·withdraw POST 경로, CSRF와 시스템 관리자 RBAC는 변경하지 않았다.
- 시스템 정책 화면 상단의 중복 `CRS 관리` 이동 버튼을 제거했다. CRS 관리는 기존 사이드바 메뉴에서 접근한다.
- 기반 CRS, 기업 정책 업데이트, 단계 배포 위젯을 정책 내용보다 위로 이동해 운영 상태를 먼저 확인할 수 있게 했다.
- 현재 운영 기준과 최초 설정 안내는 `정책 목록`, 회수·이전·재게시 기록은 `변경 이력` 탭으로 분리했다.
- 탭은 `/system-policies?tab=policies|history` 서버 렌더링 방식이며 새 프론트엔드 상태 관리나 라이브러리를 추가하지 않았다.
- 이력 검색과 상태 필터를 사용하면 `변경 이력` 탭을 유지하고, 조건 초기화 후에도 같은 탭에 머문다.

## 확인 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- Go 템플릿 파싱, CSS 중괄호 균형과 `git diff --check`를 정적으로 확인했다.
- 전체 Go 패키지와 테스트 소스가 로딩되는지 `go list -test ./...`로 확인했다. 테스트 함수는 실행하지 않았다.

## 수행하지 않은 검증

- 저장소 지침에 따라 프론트엔드 빌드와 자동 테스트는 실행하지 않았다.
- 관리자 로그인 세션이 없어 변경 후 실제 브라우저 렌더링은 확인하지 않았다.
- DB migration, init/reset, 데이터 변경과 실제 정책 배포는 수행하지 않았다.

## 추가 확인

- 변경한 Go 파일에 `gofmt`를 적용하고 관련 파일의 `git diff --check`를 확인했다.
- 현재 개발 Manager가 변경 후 다시 기동되어 `127.0.0.1:8443`에서 수신 중인 것을 확인했다.
- 저장소 지침에 따라 프론트엔드 빌드와 자동 테스트는 추가로 실행하지 않았다.
