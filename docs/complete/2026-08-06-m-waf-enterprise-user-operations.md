# M-WAF 기업 사용자 운영 권한 통합

## 완료 범위

- 기업 사용자를 조회 전용 역할에서 자기 기업의 모니터링·운영 역할로 확장했다.
- 기업 사용자와 기업 관리자 모두 서버 등록·제어·패키지 배포·등록 해제, 서버 그룹, 기업 정책 생성·전략 변경·승인·재시도·롤백을 수행할 수 있다.
- 기업 관리자는 같은 운영 권한에 더해 자기 기업의 사용자와 기업 관리자 계정·권한을 관리한다.
- 기업 사용자에게는 사용자 목록·생성·수정·삭제 화면과 API를 계속 차단한다.
- 시스템 정책 카탈로그, 기업 생성과 시스템 설정은 시스템 관리자 전용으로 유지했다.

## 사용자 관리 보호

- 기업 관리자가 자기 기업에 여러 기업 관리자를 추가하고 역할을 변경할 수 있게 했다.
- 기업 관리자는 자기 자신의 관리자 권한, 로그인 활성 상태와 계정을 해제할 수 없다.
- 마지막 활성 기업 관리자를 일반 사용자로 변경하거나 비활성화·삭제할 수 없다.
- 마지막 관리자 검사는 사용자 행과 다른 활성 관리자 행을 transaction에서 잠근 뒤 수행해 동시 변경으로 기업 관리자 계정이 모두 사라지는 것을 방지한다.
- 다른 기업과 시스템 관리자 계정은 기존과 같이 관리할 수 없으며 역할 변경은 기존 관리자 감사 로그에 기록된다.

## 호환성과 운영 주의사항

- 기존 `enterprise_user`, `enterprise_admin`, `system_admin` 값을 유지하므로 DB schema migration은 필요하지 않다.
- 기존에 등록된 `enterprise_user` 계정은 이 버전 배포와 동시에 자기 기업 운영 권한을 갖는다. 운영 반영 전에 모든 기존 기업 사용자가 신뢰된 운영 담당자인지 확인해야 한다.
- 조회 전용 계정이 필요하다면 별도 viewer 역할을 도입해야 하며 이번 통합 범위에는 포함하지 않았다.
- 기업 범위 검사, CSRF, 감사 로그, 정책 revision 충돌 방지와 서명 rollout 절차는 그대로 유지했다.

## 확인 범위

- 변경한 Go 파일에 `gofmt`를 적용했다.
- 역할 경계, 운영 route, 사용자 관리 route와 기업 관리자 간 관리 범위를 다루는 단위 테스트를 갱신했다.
- `git diff --check`와 관련 문자열·route 정합성을 정적으로 확인했다.
- DB migration·초기화·reset은 수행하지 않았다.
- 저장소 지침에 따라 Go/프론트엔드 빌드, 자동 테스트와 브라우저 실행은 수행하지 않았다.
