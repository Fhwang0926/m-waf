# 시스템 관리자 기업 소속 및 설치 범위 분리

## 완료 범위

- 최초 설정 시 `M-WAF 시스템 운영` 기업과 시스템 관리자 계정을 하나의 트랜잭션으로 생성하도록 변경했다.
- 기존 시스템 관리자도 전용 시스템 운영 기업에 자동 소속시키는 순방향 마이그레이션을 추가했다.
- 모든 관리자 계정의 `enterprise_id`를 필수 값으로 전환하고, 시스템 관리자의 전역 권한은 `system_admin` 역할로 유지했다.
- 시스템 관리자가 소속된 기업은 삭제 또는 운영 종료할 수 없도록 저장소와 관리 화면에서 보호했다.
- 설치 및 등록 화면을 기업 운영 화면으로 명확히 하고, 시스템 관리자는 기업 범위를 먼저 선택한 뒤 해당 기업의 토큰만 조회·생성·폐기하도록 제한했다.
- 내 계정과 사용자 관리 화면에서 소속 기업과 전체 기업 관리 권한을 분리해 표시했다.
- 상단 현재 범위는 시스템 관리 화면에서는 `전체 기업`, 설치 화면에서는 선택한 기업을 표시하도록 정리했다.
- 로컬 개발 감시기가 재시작할 때도 미적용 순방향 마이그레이션을 자동 적용하도록 변경했다.
- 활성 기업은 보호 서버가 없어도 DetectionOnly 기본 기업 정책과 초기 개정본을 자동 생성하도록 정책 시드 조건을 수정했다.
- 최초 시스템 운영 기업과 이후 등록한 기업은 생성 직후 정책 동기화를 요청하도록 연결했다.

## 호환 및 안전 처리

- 신규 테이블은 추가하지 않았다.
- 기존 시스템 관리자 비밀번호 복구 명령은 기업 소속 여부와 무관하게 계속 동작하도록 수정했다.
- 기존 세션은 요청마다 최신 계정 소속을 다시 읽으므로 마이그레이션 후 별도 쿠키 초기화 없이 새 범위를 사용한다.
- 기업 사용자와 기업 관리자의 기존 소속 기업 제한은 유지했다.

## 검증 범위

- Go 파일에 `gofmt`를 적용하고 변경 파일의 공백 오류를 확인했다.
- 저장소 지침에 따라 테스트, 프론트엔드 빌드, DB 초기화·리셋·직접 마이그레이션 실행은 수행하지 않았다.
- 로컬 개발 환경은 다음 `make dev` 시작부터 새 마이그레이션을 적용하며, 이미 실행 중인 이전 감시 프로세스는 한 번 재시작해야 변경된 감시 설정을 읽는다.
