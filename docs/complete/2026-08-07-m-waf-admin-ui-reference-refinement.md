# M-WAF 관리자 UI 참고 화면 기반 추가 개선 완료

## 반영 범위

- 기존 `v0.1.9` 작업 트리의 운영형 좌측 메뉴, 대시보드, 서버 표, 이벤트 상세 패널과 정책 작성 흐름을 유지했다.
- 사용하지 않는 이전 2단 상단 메뉴와 서버 카드 CSS를 제거해 현재 좌측 메뉴 구조만 남겼다.
- 좌측 메뉴의 한글 축약 문자를 외부 라이브러리가 필요 없는 인라인 SVG 선형 아이콘으로 교체했다.
- 현재 메뉴와 내 계정 링크에 `aria-current`를 연결하고 모바일 메뉴와 이벤트 상세 패널의 포커스 복귀를 보완했다.
- 좌측 하단 고정 `Manager 정상` 문구를 제거하고 실제 서명 package bundle 준비 여부와 버전을 표시한다.
- 대시보드 이벤트 추이에 축 눈금과 시간 라벨을 추가하고 차단 선을 점선으로 구분했다.
- 이벤트 30초 갱신 후에도 서버명, 요청, Rule 메시지, 상태 배지와 결과 건수 형식이 유지되게 했다.
- 이벤트 위험도에 한국어 설명과 원본 영문 등급을 함께 표시한다.
- 설치 및 등록 화면에 실제 실행 가능한 Ubuntu 24.04 LTS amd64, Apache/Nginx, distro/external 지원 범위를 카드로 표시했다.
- Windows, AIX, 다른 Linux 배포판, ARM64와 자동 Connector 컴파일이 현재 지원되지 않음을 설치 전에 확인할 수 있게 했다.
- 설치 진행 단계를 환경 확인부터 정책 적용까지 5단계로 정리했다.
- 서버와 그룹 상세에서 마지막 heartbeat 절대 시각과 함께 `방금`, `N분 전`, `N시간 전`, `N일 전`을 표시한다.
- 정책 단계 폼에서 현재 단계의 필수 입력을 확인하고 숨겨진 오류 단계로 자동 이동하도록 보완했다.
- 920px 이하에서 지원 환경 카드와 설치 단계, 상단 상태 영역이 충돌하지 않도록 반응형 규칙을 추가했다.
- 상단의 사용자명·권한·내 계정·로그아웃을 하나의 계정 메뉴로 통합했다.
- 계정 메뉴에는 `내 계정`과 `로그아웃`을 텍스트와 선형 아이콘으로 함께 표시하며 기존 `POST + CSRF` 로그아웃을 유지했다.
- 계정 메뉴는 바깥 영역 선택과 Escape 입력으로 닫히고 태블릿·모바일에서는 간결한 `계정` 트리거로 표시한다.
- 사이드바의 기업 운영 메뉴를 `사용자 영역`, 시스템 관리자 전용 메뉴를 `시스템 영역`으로 구분하고 경계선·관리자 배지로 관리 범위를 명확히 했다.
- 시스템 영역의 기존 서버 측 권한 조건을 유지해 시스템 관리자는 두 영역을 보고 기업 계정은 사용자 영역만 보도록 했다.
- 초기 렌더링 과정에서 저장된 사이드바 펼침 상태를 적용하는 동안 전환 효과를 잠그고, 초기 화면이 준비된 뒤에만 애니메이션을 활성화하도록 변경했다.
- 페이지 이동 시 반복되던 사이드바 펼침 효과는 제거하고 사용자가 접기·펼치기 버튼을 조작할 때만 전환 효과가 나타나도록 했다.

## 목록 중심 관리자 작업 흐름 추가 개선

- 사용자, 기업, 서버 그룹, 보호 서버와 기업 정책을 `페이지 제목 → 검색·필터 → 전체 폭 목록 → 상세 작업` 순서로 통일했다.
- 사용자 추가와 기업 등록은 목록 문맥을 유지하는 우측 작업 패널로 변경했다. JavaScript를 사용할 수 없는 환경에서는 기존 GET 주소로 열린 폼을 다시 렌더링해 작업할 수 있다.
- 사용자 관리에서 기업 사용자와 시스템 관리자 계정을 분리했다. 시스템 관리자 계정은 별도 읽기 전용 목록에 표시하고 기업 사용자 검색·권한·상태 필터와 섞이지 않게 했다.
- 기업이 없는 시스템 관리자에게 사용할 수 없는 사용자 추가 폼을 노출하지 않고 기업 등록을 첫 작업으로 안내한다.
- 기업 관리의 상시 등록 폼, 서버 그룹의 상시 생성·편집 폼을 제거했다. 생성과 편집을 명시적으로 선택했을 때만 최대 880px 작업 영역을 표시한다.
- 서버 그룹 목록에서 상세와 구성 편집을 분리하고, 상세 화면에서 구성원 상태와 그룹 정책 rollout을 확인하도록 정보 위계를 정리했다.
- 보호 서버는 카드 나열 대신 연결, 웹서버 통합, 정책, 패키지와 마지막 heartbeat를 비교하는 목록으로 변경했다. 서버별 제어·배포·등록 해제는 상세 화면으로 이동했다.
- 보호 서버 검색에 기업, 그룹, 연결 상태와 텍스트 조건을 제공하고 등록 해제 상태가 실제 `Revoked` 값으로 필터링되도록 수정했다.
- 기업 정책 목록에 검색, 기업, 업데이트 전략과 최근 rollout 필터를 제공했다. 시스템 관리자의 기업 필터는 활성 기업 검증을 거치며 기업 계정은 기존 소속 기업 범위로 고정된다.
- 설치 및 등록은 지원 환경, 진행 단계, 토큰 생성, 동작 설명, 발급 이력 순서의 단일 세로 흐름으로 변경했다. 토큰 원문과 설치 명령의 기존 일회 표시·복사 동작은 유지했다.
- 이벤트와 감사 로그 결과를 공통 목록 패널, 문맥형 빈 상태와 페이지 이동 형식으로 맞췄다.
- 사이드바의 운영 기능과 플랫폼 관리 기능을 별도 영역으로 표시하고 시스템 관리자 전용 메뉴의 서버 측 권한 조건을 유지했다.
- 공통 작업 패널에 제목 연결, 포커스 복귀, 바깥 영역 닫기와 모바일 전체 폭 동작을 적용했다.
- 오픈소스 CRS 목록·상세와 시스템 정책 마이그레이션 화면에 빠진 공통 `container` 레이아웃을 적용해 본문이 사이드바 경계와 겹치지 않게 했다.
- 사이드바 접기·펼치기 버튼을 메뉴 그룹 제목 높이에서 상단 브랜드 영역으로 옮겨 `사용자·서버·정책` 범위 배지와 본문 제목을 가리지 않게 했다.
- 외부 UI 라이브러리, DB 스키마와 새 API 형식은 추가하지 않았다.

## 호환성과 범위

- 기존 GET/POST URL, 세션, CSRF, RBAC, 기업 범위와 Agent API 형식은 변경하지 않았다.
- 시스템 정책과 기업 정책의 분리, 기업 사용자 운영 권한, 기업 관리자 사용자 관리 권한을 유지했다.
- 기존 enterprise install token, 일회용 token, 정책 rollout/rollback 동작을 변경하지 않았다.
- 외부 UI, 아이콘 또는 차트 라이브러리를 추가하지 않았다.
- DB 스키마, migration, 데이터 초기화와 reset을 수행하지 않았다.

## 확인 결과

- 변경한 Go 파일에 `gofmt`를 적용했다.
- `git diff --check`가 통과했다.
- 목록 필터와 작업 패널 변경 후 Go 파일에 `gofmt`를 다시 적용하고 `git diff --check`를 재확인했다.
- 현재 실행 중인 로컬 Manager에서 로그인 화면과 갱신된 내장 `app.css` 응답을 확인했다.
- 실행 중인 CSS에 좌측 SVG 아이콘, 차트 축, 설치 지원 환경 스타일이 포함된 것을 확인했다.
- Manager는 시작 시 모든 Go 템플릿을 함께 파싱하므로 갱신된 내장 CSS가 제공되는 현재 프로세스에서 템플릿 초기화도 완료된 상태다.

## 수행하지 않은 확인

- 저장소 지침에 따라 자동 테스트와 프론트엔드 빌드는 실행하지 않았다.
- DB migration 적용, 초기화와 reset은 수행하지 않았다.
- 로컬 브라우저에 관리자 인증 세션이 없어 대시보드, 설치 및 등록, 정책, 서버 상세의 로그인 후 시각 검증은 수행하지 않았다.
- 실제 Agent heartbeat, 이벤트 유입과 rollout 상태가 있는 운영 데이터 통합 검증은 별도 환경에서 필요하다.
