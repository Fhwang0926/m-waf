호스팅사를 위한 소프트웨어 웹방화벽

웹서버는 그대로,
보안 운영은 중앙에서

M-WAF는 기존 Apache·Nginx의 요청 처리 경로에 검증된 ModSecurity와 OWASP CRS를 적용하고, 여러 고객 서버의 정책과 보안 이벤트를 별도 Manager에서 통합 관리합니다.

배포 방법 확인 제품 기준 비교

오픈소스 탐지 엔진을 변경하지 않고 운영에 필요한 관리 계층만 최소한으로 구현한 MVP입니다.

제품 원칙

새 탐지 엔진보다
운영 가능한 구조에 집중합니다

고객 트래픽을 중앙 장비로 우회하지 않습니다. 각 웹서버가 독립적으로 검사와 차단을 수행하고, Manager는 정책·패키지·로그의 중앙 관리만 담당합니다.

01

기존 인프라 유지

Apache·Nginx와 기존 80/443 서비스 경로를 유지하므로 별도 프록시 장비나 네트워크 재구성이 필요하지 않습니다.

02

고객 설치 범위 최소화

고객 서버에는 공통 정책관리 Agent와 해당 웹서버용 ModSecurity 모듈, 두 패키지만 설치합니다.

03

오픈소스 우선

ModSecurity와 OWASP CRS 원본을 사용하고, M-WAF는 배포·서명·롤백·로그 수집에 필요한 관리 기능을 제공합니다.

운영 아키텍처

차단은 로컬에서,
관리는 별도 서버에서

Manager 장애가 웹 요청 경로에 영향을 주지 않도록 데이터 플레인과 관리 플레인을 분리합니다. 각 서버는 마지막으로 검증된 정책을 계속 사용합니다.

운영 경계

웹 요청은 Manager를 경유하지 않습니다. Agent가 Manager로 연결하는 관리 통신만 사용하므로 고객 서버에 M-WAF용 인바운드 포트를 추가하지 않습니다.

MVP 제공 범위

배포와 운영에 필요한
핵심 제어 기능

Go 표준 라이브러리 중심의 Manager·Agent와 MariaDB, Docker Compose로 구성하며 별도 메시지 브로커나 검색 클러스터를 요구하지 않습니다.

Package Control

환경 일치 패키지 제공

OS, CPU, 웹서버 버전과 빌드 해시가 catalog와 모두 일치할 때만 Agent·모듈 설치 파일을 제공합니다.

Policy Safety

서명·검증·자동 롤백

Ed25519 서명과 SHA-256을 확인하고 웹서버 설정 검사에 성공한 경우에만 reload합니다. 실패하면 직전 정책으로 복구합니다.

Secure Channel

Agent별 mTLS 통신

일회용 등록 토큰과 Agent별 인증서를 사용해 정책 조회, heartbeat, 이벤트 전송 경로를 보호합니다.

Event Collection

감사 이벤트 배치 수집

ModSecurity JSON 이벤트를 로컬 디스크에 임시 보관하고 최대 500건 단위의 멱등 batch로 Manager에 전송합니다.

Access Control

기업 단위 관리자 분리

시스템 관리자, 기업 관리자, 기업 사용자 역할을 구분하고 서버와 보안 이벤트 조회 범위를 기업 단위로 분리합니다.

Single Distribution

Manager 중심 배포

동일 commit에서 생성한 Agent와 Apache·Nginx 모듈을 Manager 이미지에 포함해 설치 버전의 출처를 하나로 유지합니다.

벤치마크 제품 비교

DeepFinder를 기준으로 본
M-WAF의 현재 위치

DeepFinder는 웹서버에 소프트웨어 모듈을 설치하고 Manager에서 여러 Agent를 관리하는 상용 WAF입니다. M-WAF는 이 운영 모델을 참고하되, 오픈소스 구성요소로 먼저 실행 가능한 최소 범위를 구현합니다.

비교 자료와 해석 범위

DeepFinder 항목은 2026-08-06에 확인한 공급사 공개 매뉴얼의 제품 구성·특징, 정책관리, 보안패턴 내용을 요약했습니다.

기능 보유 여부와 공급사 설명을 비교한 자료이며, 양 제품의 탐지율·처리량·안정성을 동일 환경에서 독립 시험한 결과가 아닙니다. 특히 DeepFinder의 Agent 규모와 성능 표현은 공급사 매뉴얼 기준입니다.
