# M-WAF Bootstrap CA 자동 다운로드 적용 완료

## 작업 목적

Agent 빠른 설치 명령에 M-WAF CA 인증서 원문을 Base64로 포함해 명령이 길어지던 문제를 줄이고, 최초 신뢰 설정을 설치기 내부에서 안전하게 처리하도록 개선했다.

## 반영 내용

- Manager가 공개 CA 인증서를 `/bootstrap/v1/ca.crt`에서 제공하도록 추가했다.
- Manager 시작 시 현재 TLS 인증서의 SPKI SHA-256 공개키 핀을 계산하도록 추가했다.
- 빠른 설치 명령에서는 CA Base64 원문 대신 짧은 TLS 공개키 핀만 전달한다.
- 설치기 최초 다운로드는 `--insecure` 단독 사용이 아니라 `--pinnedpubkey`를 함께 사용해 Manager 공개키를 확인한다.
- 설치기는 `--ca`가 없으면 같은 공개키 핀으로 Manager CA를 직접 내려받는다.
- CA를 내려받은 뒤 등록 세션, 패키지 조회·다운로드와 Agent 통신은 기존처럼 `--cacert` 기반 정상 인증서 검증을 사용한다.
- 자동화 환경에서 CA를 미리 배포하고 `--ca`를 전달하는 기존 설치 방식도 유지했다.
- 기존 컨테이너·systemd 실행 감지와 Agent 전용 1단계 설치 흐름은 유지했다.

## 보안 기준

- CA 또는 설치기를 검증 없이 내려받지 않는다.
- TLS 검증 예외는 짧은 최초 다운로드에만 적용하며 반드시 현재 Manager TLS 공개키 핀을 함께 확인한다.
- 기업 설치 토큰 원문은 명령에 포함하지 않고, 빠른 설치는 기존 15분 일회용 등록 토큰 파일을 사용한다.
- 내려받은 CA는 Agent 설정에 저장한 뒤 모든 정상 통신의 신뢰 기준으로 사용한다.

## 확인 범위

- 프로토콜 경로, Manager 라우트, 공개키 핀 계산, 설치 화면과 Bootstrap 설치기 흐름을 함께 갱신했다.
- CA Base64 복원 명령이 빠른 설치 명령에서 제거된 것을 정적으로 확인했다.
- 기존 `--ca` 설치 경로가 유지되는 것을 확인했다.
- 현재 실행 중인 `https://192.168.7.10:8443`에서 TLS 공개키 핀으로 `/bootstrap/v1/ca.crt`를 내려받고 로컬 M-WAF CA와 일치하는 것을 확인했다.
- 내려받은 CA로 새 설치기를 정상 수신하고 `--bootstrap-pin`과 CA 자동 다운로드 로직이 포함된 것을 확인했다.
- `git diff --check`를 확인했다.

## 수행하지 않은 검증

- 프로젝트 지침에 따라 별도 빌드와 자동 테스트는 수행하지 않았다.
- 실제 원격 Ubuntu/Debian 서버에서의 Agent 설치는 수행하지 않았다.
- DB 조회·변경, init, reset, 스키마 마이그레이션은 수행하지 않았다.
